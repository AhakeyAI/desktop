## UI 布局与目标选择

沿用左侧键盘 Mode 选择和 OLED/灯条热点，右侧内容随热点切换。
OLED 右侧为 Mode N · OLED，下设 默认屏幕 / SINGLE / MULTI 三个分组入口。
首次进入默认选中当前 Mode 默认屏幕；默认分组一格、SINGLE 三格、MULTI 三格。
不是一次显示十九格，也不是七份全局 MULTI 副本。
资源格有目标名称、X / Y 帧、状态、选择文件/更换文件、清除；底部统一 上传并应用 和刷新。
切换 Mode 自动重新绑定模式资源和左侧预览；MULTI 仍是同一份全局资源。
具体“切模式是否保留 SINGLE 子状态选择”是 DLA 提案：保留分组/状态，只替换 Mode 维度；
首次进入才默认屏幕。它不是历史 Owner 确认，随本合同一次批准。
上传过程中 UI 禁止切换上传目标、Mode、文件、清除及竞争的设备写入；
物理键盘模式变化不能改变已冻结的上传目标，也不得把迟到结果写到新格。

固定文案：
> 多任务状态是全局资源，不跟随某一个模式单独保存。这里的 GIF 用于多槽位场景下主槽位 AI 的状态变化。

## OLED 本地体验

- 左侧键盘 OLED 热点的 overlay 是唯一主预览；不是右侧重复放一个原图预览。
- 最终画布 160×80，等比完整显示、黑边、透明合成黑底；以实际 RGB565 成品还原预览，
  不以 JavaFX 原图路径直接播放来冒充设备效果。绘制尺寸可等比缩放，内容坐标始终 160×80。
- GIF/PNG/JPG/JPEG；静态图按 1 帧。默认上限 8，状态上限 12；统一显示 X / Y 帧。
- 完整解码 GIF 的逻辑画布、局部帧偏移和 disposal；不能将原始局部帧独立缩放，不能静默截帧。
- 保留现有源文件2MiB限额，后台解码并限制解码资源占用；这是本轮提案，不冒充历史确认。
- 超限弹窗：当前 GIF 有 X 帧，目标位置最多支持 Y 帧。请减少帧数。
- 文件解码/编码/保存失败弹窗给具体原因，文件不适用即可，不添加“换文件或发给我们”等建议。
- 成功选择并完成处理后立即出现预览、标为草稿，右上角显示草稿标注，持久保存。
  处理过程中显示处理中，不提前把失败文件写为可上传草稿；替换失败保留原可用资源。
- 不提供颜色调节、不提供设备 OLED/GIF 预览。旧 FPS/标题/说明编辑不进入 CP2 设备配置。
  固件当前每帧固定 100ms；成品预览同步按 10fps 播放，不承诺保留原 GIF 可变时长。
  此 FPS 收口是固件事实引出的明确提案，纳入本轮最终范围确认。
- 选中资源预览保持到清除或切格，重启软件仍可恢复；设备显示时机由固件决定。

## 本地资源库与状态

结构与清理提案：用户目录 .ahakey/oled-resources/v1，index.json + 每个 entry 的成品文件。
只存处理后 160×80 帧/上传字节、格式版本、目标、帧数、CRC、草稿状态及最后设备确认信息。
第一版不按设备建库；可保存本次连接身份作校验上下文，但不是按设备分库。
原始文件只是导入输入，不作为重启后依赖，不修改/删除用户原始文件。
索引和成品采用临时文件完成后替换的提交方式，写盘失败不得假装草稿已持久保存。
不按年龄/启动/退出自动清理；显式清除只删当前资源格所属本地文件和索引，
共享引用不得误删，其他格/按键/语音/日志不动。无引用旧版本暂保留，不加自动配额清理。
路径子目录与清理细节属于本轮提案，不冒充之前孤立的“确认/保留”已决定具体实现。
旧 studio-draft.json 保留其他配置；旧 OLED 源路径可读取时迁移为对应 Mode 默认资源草稿，
路径失效时不伪造设备已有/已应用。迁移幂等且不覆盖新库条目。

业务状态为 空态 / 草稿 / 上次失败 / 已应用 / 设备已有；处理中、上传中、同步中是操作状态。
本地草稿与设备事实分别持有。刷新不覆盖草稿；清除本地不改变设备配置。
没有本地成品且设备有效：黑底占位，只写“设备已有”。
曾已应用但当前完整元数据不匹配：降级草稿并轻提示
“本机预览和当前键盘不一致，已作为草稿保留。”
离线/读取失败只是当前设备事实未知，不凭超时将本地数据删除或设备判为空。
上传按钮只允许当前格为草稿/上次失败，且成品完整、连接已准入、无竞争事务。
同文件重新选择成功也立即为草稿，不因 CRC 相等自动跳过用户明确替换。
清除已应用格或持有已应用设备基线时提示：
“这只会清除本机草稿和预览，不会删除键盘上已应用的资源。”

## 上传与应用

弹窗只确认冻结目标，无可编辑选择器；例：确认上传到 Mode 2 · 默认屏幕？
MULTI 目标以“全局 MULTI · 运行中/等待中/已完成”表示，不能标为某个 Mode 独占。
确认后进入上传中，底部按钮 loading，显示 已确认字节百分比 或 完成帧/总帧。
0x8A → 顺序0x8B → 0x8C，逐包应答，绝不使用旧 raw write / 0x82 路径。
Begin 成功即失去旧用户资源有效性；Begin返回FAIL也可能已写过WRITING并转INVALID，
不能依据单一FAIL保证旧资源保留，须回读核实。Commit 成功才持久生效。
正常 Commit ACK 后提示“已应用到 Mode 2 · 默认屏幕。”，不承诺立即在键盘播放。
失败保留本地成品作为上次失败可重试；断连不跨连接续传，不自动重发 Chunk。
ACK 丢失不能断言设备一定未保存：Commit 发出后结果不明需重读 BASIC+INTEGRITY 对账；
不能把“键盘原资源不会被替换”作为通用失败文案。
完整失败/未知恢复规则见 PROTOCOL_AND_STATE.md，尤其 ACK 丢失与同连接事务未结束。

## 灯光

右侧沿用全局亮度和当前 Mode 九项 SINGLE AI 状态灯效；不压缩成三项、不新增 MULTI 灯效配置。
亮度保留 1..100 数值控件，测试改名“预览”，独立保存亮度；灯效区保留下拉/逐项预览和保存当前 Mode。
下拉/亮度编辑只改草稿，不自动发设备命令。保存当前 Mode 不顺带保存全局亮度。
预览使用0x89，临时10秒；亮度预览固定第一个可见内置灯效 SINGLE_MOVE。
OFF 可保存、不可设备预览；左侧可显示熄灭。成功0x8E才更新保存基线；保存失败保留草稿。
九项批量保存本质是逐项0x8E，不具有原子性；中途失败标明失败项，已确认项不伪装回滚，
未保存项保留草稿，不能将整个 Mode 标成功。
左侧显示固件同源八灯珠效果模拟，复用键盘区域，不造独立大预览面板。
以固定相位/时间输入对照固件颜色、强度、运动顺序；不保证屏幕与实体灯光的光度完全一致。
设备预览提示只在 ACK 后建立，界面不把本地模拟当设备已接受；离开面板不补发 STOP。
0x8E任一保存成功会由固件停止preview，Windows收到成功ACK同步撤销设备预览提示；
保存失败不重新开始10秒。保存ACK未知则预览/保存结果均标待核实，不继续套用旧倒计时事实。
0x89/0x8E没有请求序号；超时后不得在同一会话继续发可混淆的新写请求，须按隔离规则恢复。
编辑过程中断连仍能本地编辑/模拟，所有设备预览/保存禁用；重连不自动保存、不覆盖草稿。
当前热点在源码中并未要求连接才能选中，因此保留现有离线浏览能力，不增连接门槛。
