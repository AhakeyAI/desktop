## 5. User Purpose

The Windows Desktop should follow the keyboard's real current mode, support a
Desktop-initiated mode switch only when the firmware confirms it, preserve local
draft edits while disconnected, and show a compact status summary that users can
understand without reading raw protocol values.

## 6. User Journey Binding

Primary journey:

- User connects the keyboard over USB or BLE.
- Windows reads the keyboard-authoritative current mode.
- If the user changes mode from the keyboard Power key, Windows follows after
  status polling/query.
- If the user changes mode from Windows, Windows sends the existing mode-set
  command and only treats it as success after firmware acknowledgement and
  readback match.
- If disconnected, Windows allows browsing/editing local drafts but blocks
  apply/sync operations.
- On reconnect, Windows reads keyboard truth first and preserves unapplied
  drafts as local drafts.

Firmware-side module references:

- `MOD-003` Mode Toggle Sync, primary CP4A module.
- `MOD-004` Configuration Schema / local drafts boundary.
- `MOD-006` Display / status summary ownership.
- `MOD-013` USB Device Transport.
- `MOD-014` BLE Transport.

## 7. Protocol Summary

CP4A uses existing protocol commands. It does not introduce a new command number.

- Existing `0x00` status readback supplies keyboard-authoritative current mode
  and status fields used by Windows after connection, polling, keyboard-side
  mode changes and Desktop-side confirmation.
- Existing `0x92` Desktop-to-keyboard mode set carries one valid target mode
  byte.
- A Desktop mode set is successful only after `0x92 OK` and a follow-up `0x00`
  readback reports the requested mode.
- Non-OK response, timeout, disconnect or readback mismatch is a failure; Windows
  must return visible state to keyboard-authoritative mode.
- USB and BLE are expected to expose equivalent behavior for this journey.
- The active Desktop control channel owns mode-set attempts while connected.

## 8. Windows-Side Expected Behavior

- Read current mode from the device through existing status readback.
- Keep the visible mode aligned with keyboard-originated mode changes.
- Allow Desktop-originated mode switch only while connected.
- Send `0x92`, then require `0x00` readback match before success UI/state.
- On failure, timeout, disconnect or mismatch, return to keyboard truth and show
  a recoverable failure state.
- While disconnected, allow local browsing/editing but disable Save/Apply and
  any `0x92` apply path.
- On reconnect, read keyboard truth first; do not replay stale local draft state.
- Preserve unapplied local drafts as drafts.
- Show mode summary with primary key labels, battery percent, charging state and
  readable connection/status labels.
- Preserve existing Mode1/2/3 visuals; Mode4 remains empty/placeholder until a
  later scope authorizes more.
- Preserve WD-001 recovery expectations for `0x95` sleep timeout and `0x9F`
  firmware catalog key.
