## C2. 登录、注册及账号刷新反馈（已确认）

旧版事实：CloudAccountDialog.submit显示通用“请求中”并开线程，无显式重复提交按钮禁用；CloudAccountManager.authenticate会接受登录token，注册无token时提示注册成功请登录；仅资料很少时补刷新。refreshProfile在401/403等失效时清会话，普通网络错误不主动清会话。旧authenticate把大多数异常统一成登录失败/注册失败，需改善真实原因反馈。

建议沿用窗口底部提示区域，不为每次网络错误另弹警告框；等待文字与按钮状态明确区分操作：

| 场景 | 窗口文案/行为 |
| --- | --- |
| 手机号或密码为空 | 输入处提示“请输入手机号/密码”，不发送请求；不擅自添加后端未定义的密码规则 |
| 正在登录/注册 | 对应按钮显示“登录中…”或“注册中…”，暂禁两种重复提交及修改当前请求字段；窗口仍可关闭，UI线程不阻塞 |
| 登录成功 | 切换账号页并刷新资料/额度，显示“已登录，正在获取账号信息…”；禁止只凭登录成功显示云端整理可用 |
| 注册成功且有效会话已返回 | 显示注册成功并进入账号页，再获取资料 |
| 注册成功但没有有效会话 | 留在登录页，显示“注册成功，请登录”；保留已输入信息，不假装已登录，不暗中重复注册 |
| 明确凭据或注册业务错误 | 原页面显示经校验适合展示的后端原因；未知错误显示通用失败，不猜测“密码错误”；保留输入供修正，不在日志中输出密码 |
| 登录网络失败/超时 | “暂时无法连接云端，请检查网络后重试”，恢复按钮；不标成密码错误 |
| 注册请求超时，提交结果不明 | “暂时无法确认注册结果，可尝试登录”，不自动重新注册 |
| 已登录但资料/额度刷新失败 | 保持账号页；已有数据注明未刷新/上次获取，首次缺失显示未获取；提示“账号信息刷新失败，请重试”，提供刷新账号 |
| 已确认会话失效 | 显示“登录已过期，请重新登录”并回登录页，不保留旧账号的可用额度/支付动作；原文回退沿AhaType后续约定 |
| 本地保存失败 | 区分“云端登录/刷新已成功，但本地保存失败”，不得假报登录持久化成功或保存了密码；不自动重复云端写操作 |

Owner已确认此组登录/注册/刷新反馈，依据 evidence/20261105-wd010-cloud-c2-owner-decision.md。是否保持会话、记住密码的具体语义、退出及关闭窗口时迟到响应随后单独细化；不借本轮批准擅自修改会话政策。
已知技术约束：重复点击只能一个相应请求；刷新/登录结果绑定账号及请求代次；旧窗口或退出后的迟到回复不能更新新会话；不把每次失败变成清token，不把每次登录成功变成有有效套餐。在线服务行为仍需受控验证，不能以客户端期望代替实际API契约。

## C3. 记住密码、保持登录及主动退出（已确认）

Owner选择“采用这套行为（推荐）”，依据 evidence/20261105-wd010-cloud-c3-owner-decision.md。以下产品规则已确认，具体安全存储及兼容实现仍需技术核验。

旧版源码事实：CloudAccountManager构造调用refreshLocalState，使用保存的会话和profile恢复登录展示；AhaTypeService把rememberPassword与token分开保存，clearSessionKeepToggle清会话/额度但保留开关和记住的凭据。旧版保存密码字符串的实现不是本轮安全存储依据。

建议产品规则：

| 用户操作/状态 | 建议结果 |
| --- | --- |
| 正常关闭账号窗口 | 不退出账号，不影响有效会话 |
| 退出软件后重新打开，有有效登录态 | 恢复登录并刷新账号；先区分上次资料与已联网确认的最新资料，不借恢复会话宣称云端当前可用 |
| 未勾记住密码 | 不保存/回填密码，但仍允许上述有效会话恢复；记住密码旁提示“下次登录时自动填写密码” |
| 勾选记住密码 | 下次需要登录时回填手机号和密码；不因有保存密码就自动发送登录请求 |
| 取消勾选记住密码 | 删除此前保存的密码；失败需提示未能清除，不能显示已清除却保留；不因此自动注销当前会话 |
| 主动退出登录 | 清除本地会话和账号/额度事实，回登录页，不自动重新登录；若原先勾选记住密码，保留回填但必须用户点击登录 |
| 登录过期 | 回登录页；按记住密码选择回填，不静默尝试旧密码重新登录 |

“保持登录”受真实会话有效性约束，不保证永不过期，不把套餐/服务到期当作登录token失效。默认记住密码不勾选，已有明确保存偏好按兼容设计处理。密码存储需采用受保护的方案，不复制历史明文存储；失败明确反馈，不降级到明文。具体实现及旧配置迁移由技术核验收敛，不要求Owner选加密算法。
本轮只确认这套会话/回填产品语义。退出时使旧登录、刷新、文字整理、支付查询回调失效，不能让迟到响应复活账号；网络线程与窗口关闭后的生命周期需要对应测试。忘记手机号、换账号、支付中退出等跨功能细节随对应窗口继续收敛。

## C4. 兑换码窗口与结果不确定（已确认）

Owner选择“采用这套兑换流程（推荐）”，依据 evidence/20261105-wd010-cloud-c4-owner-decision.md。该确认不等于线上接口或幂等性验证。

只读旧版 f6c7a5c8：CloudAccountDialog.redeemCoupon 使用输入弹窗，提交后回账号页执行；CloudAccountManager.redeemCoupon 将兑换码去除首尾空白，向 POST /api/v1/coupon/redeem 提交 code 和当前 token，成功后刷新账号。成功但刷新失败已有单独文案；普通异常统一“兑换失败，请稍后重试”，不能准确表达请求已提交而响应丢失。已查阅的客户端流程未见按兑换码查询结果的接口，未验证线上幂等性。

建议独立小窗口，标题“兑换码”，显示目标账号、兑换码输入框、提示“兑换将计入当前账号”，按钮“取消”和“确认兑换”。空值本地提示；仅去掉首尾空白，不改大小写或猜测编码规则。

| 场景 | 建议文案和操作 |
| --- | --- |
| 提交中 | 显示“正在兑换…”，禁止修改本次输入和重复提交；关闭窗口不会撤销已提交请求，再打开沿用当前操作状态，不重新提交 |
| 服务端明确兑换成功 | 显示“兑换成功”，刷新账号有效期及额度；清空已成功的码，不虚构兑换所得时长/额度 |
| 兑换成功但刷新失败 | “兑换成功，但账号信息刷新失败”，提供“刷新账号”，不再兑换 |
| 明确业务拒绝 | 窗口内显示适合展示的原因，保留输入可修正；“已使用”不能自动解释为本账号此次兑换成功 |
| 超时/断网且不能证明请求未提交 | “暂时无法确认兑换结果，请先刷新账号查看权益”，提供“刷新账号”和“关闭”，不自动重发兑换；刷新账号不等于能确认该兑换码处理结果 |
| 登录已确认失效 | 提示“登录已过期，请重新登录”，不自动重提兑换；重新登录后的继续兑换需用户主动提交 |

同一账号已有请求未结束时不得因关闭/重开另发请求。超时后的人工再次提交应明确告知上次结果未知，不把任意重复提交称为安全重试；后台不新增未经证实的结果查询接口。操作绑定原账号和会话代次，退出/换账号后迟到结果不得更新新账号，也不得把旧码自动带到另一账号；不在日志或持久化记录里保存完整兑换码。退出及窗口生命周期实现须覆盖迟到响应。

## C5. 微信充值：沿用旧版（Owner已决定）

Owner要求“按照原来的这个代码里面是怎么实现，具体实现就好了”，依据 evidence/20261105-wd010-cloud-c5-owner-decision.md。实际范围采用以下已查明的旧版流程；本节后半的此前提案仅保留历史，不作为DIB实现要求。

- 账号页点击微信充值，使用套餐选择弹窗，云端价格支持的包月/包季/包年可选；没有可用套餐则提示。
- 确认套餐后创建订单，另开微信扫码支付窗口，显示支付金额、二维码、关闭按钮。
- 约每2秒查询订单，轮询期限3分钟；服务端确认支付成功后刷新账号并反馈，服务端明确失败单独反馈。查询超时仅代表客户端未确认，不能证明未支付或服务端订单已失效。
- 关闭二维码窗口或账号窗口停止相关轮询；不取消服务端订单。按旧版不新增重启订单恢复、订单历史、手动查询按钮或持久化支付链接。重新发起充值仍由用户主动选择套餐；不自动重新建单。
- 旧版缺失订单金额时使用已选套餐金额，该行为作为历史依据记录，不冒充已获取订单金额；解析/有效性问题由实现核查。
- 保留C2已确认的真实刷新反馈：服务端已确认支付，但刷新资料失败，显示“支付成功，但账号信息刷新失败”，不能沿用旧版无条件声称额度已刷新的逻辑。旧账号迟到回调不能更新新账号。

### 旧版来源及此前提案（新增提案未采用）

旧版 f6c7a5c8 的 CloudAccountManager.getRechargePlans 从 policy.recharge_prices_fen 中提取 monthly/quarterly/yearly 的正数分值，名称由客户端映射；没有价格的套餐不显示。createWechatOrder POST /api/v1/payment/wechat/native 仅提交 plan，返回订单号、支付链接和金额，旧版缺失金额时回退套餐价格。CloudAccountDialog 用 ChoiceDialog 选套餐，独立 Stage 显示金额、二维码和关闭按钮。后端实际支持套餐/价格未在线验证，不预填猜测价格或销售承诺。

建议保留“微信充值”独立窗口，先展示当前充值账号、可用套餐名称及价格、明确返回的权益说明；未知权益不编造。套餐来自成功获取的当前账号政策，缺少可用价格时显示“暂未获取可用充值套餐”与“刷新套餐”，不生成订单。选择后点击“生成微信支付二维码”才创建订单，不因打开窗口或选择套餐就请求建单。

同一窗口切换为“微信扫码支付”：账号、套餐、订单金额、订单号（可复制）、二维码、状态提示，以及“查询支付结果”“关闭”。订单创建中禁重复点击；已有同账号订单窗口优先聚焦，不因重复入口点击另建订单。只展示服务端明确的过期时间，不虚构倒计时。

订单缺失金额、金额非法或与用户选择时价格不同，不能套用历史回退金额后直接显示二维码。缺失/非法时说明无法确认订单金额；价格变化时先展示原价/新价供用户确认，再显示已创建订单的二维码，不为确认动作自动重复建单。点击关闭不声称已取消服务端订单。

付款成功/失败/结果未知的文案、查询重试、窗口关闭/软件重启、建单超时无订单号及换账号行为下一轮接续；本轮只确认套餐到扫码的界面和建单触发点，不批准真实付款操作。

## C6. AhaType最终文字输出（已确认）

Owner选择“沿用旧版顺序和20秒超时（推荐）”，依据 evidence/20261105-wd010-cloud-c6-owner-decision.md。

旧版AhaTypeService.processIfEnabled对本地最终识别文字POST /api/v1/typeless/process，发送text与Bearer token，读取非空data.text/result；请求超时20秒，连接超时15秒。VoiceInputManager在后台worker完成后才调用结果回调并注入文字；不先输出原文再补一份优化文本。关闭AhaType、未登录、服务到期、请求失败等返回原文。系统Win+H路径不经过这个本地最终结果接缝。当前1.0.19缺少该服务与调用，源码及实际包隔离证据见INVESTIGATION.md。

建议沿用旧版输出顺序及超时：识别结束后提示“正在整理文字…”，后台等待成功返回并只输出一次优化文字；失败/超时输出一次原文并提示原因。开关关闭直接输出原文。取消本次输入或开始下一次录音后，旧请求即使迟到也不能再注入；这是保留当前语音生命周期，不整体拷贝旧VoiceInputManager。此处不承诺后端模型、提示词或优化效果，尚无线上验证。
