# WD010 恢复功能 UI 与异常场景草案

状态：Owner确认六项主流程后要求继续细化。A确认窗口内容、A2进度/异常窗口文案与按钮、A3软件重启提示及同设备只读查询行为已于2026-11-05确认；其余细节继续核对，不新增实施批准。依据 evidence/20261104-wd010-ui-detail-owner-steering.md 及 evidence/20261105-wd010-restore-ui1/ui2/ui3-owner-decision.md（各独立文件）。

## A. 首次确认窗口（内容已确认）

沿用现有JavaFX窗口与dialog-card风格，不引入全局设计重构。建议可缩放、长内容可滚动；底部按钮固定可见，设备名过长可换行。

标题：恢复出厂设置
目标设备：真实设备名称 + 可区分同名设备的标识（展示信息不足时不得假装已锁定设备）。

已确认正文：
```
将恢复这台设备的出厂配置：
• 所有模式的按键、宏、拨杆和语音设置
• 待机、灯光及显示设置
• 自定义图片/GIF将不再使用，显示恢复为默认内容

蓝牙配对、设备名称和固件版本将保留。
电脑上的云端账号不受影响。

你还有未保存的设备配置，确认后将一并丢弃。
（仅存在目标设备草稿时显示这一行）

请保持设备连接USB电源。
操作开始后无法撤销，关闭窗口也不会停止恢复。

[取消]                       [确认恢复出厂设置]
```

默认焦点取消；Esc/右上关闭与取消相同，未确认时零恢复命令。确认期间目标改变或断连，原确认失效，不沿用到新设备。不能只改弹窗设备名称然后让原确认继续生效。
“自定义图片/GIF不再使用”对应metadata失效，不宣称彻底擦除；电脑图片文件不删除。上述具体内容已确认；窗口尺寸、视觉层级与按钮样式尚未逐项定稿，不要求Owner重新决定协议清除范围。

## A2. 同一进度/结果窗口的具体内容（文案与按钮已确认）

固定标题“恢复出厂设置”，顶部持续显示原目标设备名称及标识，不跟随当前选择静默换成其他设备。主体显示状态图标/不定进度动画、状态标题和说明，底部按当前状态换按钮。正常阶段不是人为定时播放，设备若直接返回COMPLETE可跳过未观察到的中间阶段。

| 实际状态 | 状态标题 | 说明文案 | 按钮 |
| --- | --- | --- | --- |
| 请求已发送，尚无匹配确认 | 正在等待设备确认 | 请保持设备连接USB电源。关闭窗口不会停止已开始的恢复。 | 关闭窗口 |
| 匹配状态确认IN_PROGRESS | 正在恢复出厂设置 | 请保持USB供电。关闭窗口后，软件将继续查询恢复状态。 | 关闭窗口 |
| 匹配状态COMPLETE，尚未完成读回 | 设备已恢复，正在读取配置 | 正在同步设备当前配置，请稍候。 | 关闭窗口 |
| 匹配完成状态且必要配置读回成功 | 恢复完成 | 已同步设备的出厂配置。 | 完成 |
| 通信中断/查询超时，结果未知 | 暂时无法确认恢复结果 | 设备可能仍在恢复。请保持USB供电，并连接原设备后重新查询。 | 关闭窗口、重新查询 |
| 固件明确报告INCOMPLETE | 恢复未完成 | 请保持USB供电并检查设备连接，再重新发起恢复。 | 关闭窗口、重新恢复 |
| 设备COMPLETE，必要配置读回失败 | 设备已恢复，配置读取失败 | 请检查设备连接后重新读取，无需再次恢复出厂设置。 | 关闭窗口、重新读取 |

“重新查询”只查恢复状态；“重新读取”只同步配置；“重新恢复”必须重走已确认的确认弹窗、检查条件并获取新attempt，绝不静默重发。未连接时按钮点击解释需要连接原设备，不转向新设备。查询/读回进行中禁用对应重复请求按钮；无恢复取消按钮。关闭/右上X/Esc仅隐藏进度窗口，不取消后台任务；完成按钮关闭结果页。
结果未知状态停止不定动画并显示提示图标，避免暗示知道设备正在执行；未完成用警示图标；完整成功才用成功图标。所有状态均不显示未经设备提供的百分比。
本表窗口内容与按钮安排已获Owner确认；超时阈值、查询退避、重连关联和设备写入锁仍需结合实现证据收敛，不因Owner接受文案而自动获得任意技术策略批准。

## A3. 断连、换设备及软件重启（具体方案建议，继续Grill）

| 场景 | 可见内容和建议行为 | 约束 |
| --- | --- | --- |
| 恢复中原设备断连 | 原进度窗口保留原目标，停止不定动画，显示“暂时无法确认恢复结果，请连接原设备后重新查询” | 不自动重新执行恢复，不把断连当失败或成功，不为了查结果偷偷切换当前目标 |
| 用户按现有方式重新连上原设备 | 身份核对通过后只读查询；窗口若已开则更新，已关闭则不抢焦点重开 | 不使用旧连接回复；匹配本次attempt后再关联结果，后台查询不等于后台重新恢复 |
| 当前连接了另一台设备 | 旧任务仍显示“等待原设备连接”，另一台设备的状态不能填进旧结果 | 名称相同不足以判同一设备；不对另一台设备发旧任务命令。是否允许另一台正常操作需结合单目标维护锁设计明确 |
| 重新打开软件，有待核实恢复记录 | 建议主窗口提示“上次设备恢复结果尚未确认”，提供“查看进度”；默认不强制弹出独立窗口 | 原设备未连接时不自动选目标；连接原设备后先查状态，再按真实结果更新，不重发恢复 |
| 本地没有本次关联记录，但设备返回COMPLETE | 不宣称刚刚替用户完成了一次恢复；显示读取到的设备当前状态 | 历史COMPLETE与本轮完成区分；不凭本地提示自动丢弃新草稿或触发新恢复 |
| 跨通道或重启后无法证实原设备 | “暂时无法确认是否为原设备”，保留未确认记录 | 不仅凭型号、固件版本、设备名或同一USB端口认回；不让一次普通查询结果替代设备身份 |

UI3已确认：软件重启发现未确认任务时，主窗口提示“上次设备恢复结果尚未确认”并提供“查看进度”，不强制弹窗；同一原设备重新连接、身份核对后只查询状态，另一设备不承接旧任务。依据 evidence/20261105-wd010-restore-ui3-owner-decision.md。其余技术关联继续核验，不重问协议事实。

实现前须解决：最小待核实任务记录（原设备可验证标识、恢复attempt及提交阶段）、原子保存/读取失败处理、跨重启身份解析、超时/退避/退出线程释放。当前BleManager/StudioController已有connectionGeneration校验；FirmwareIdentity含catalogKey而非唯一硬件身份；维护Identity的container/port比较是现有维护流程事实，不能未经论证直接当跨通道/跨重启唯一设备证明。日志不是恢复结果；软件启动不得恢复旧待发送写请求。

### A3补充：无法自动识别时的人工关联（已确认）

2026-11-05 Owner确认：显示上次目标和当前连接，提供“确认这是原设备并查询”。仅在没有可靠自动识别依据且未发现明确身份冲突时提供；点击只建立人工关联并查询，不重发恢复。返回attempt必须匹配原任务；人工确认不记为硬件身份验证成功。用户不确认、次数不匹配或明确为其他设备时保持结果未确认。依据 evidence/20261105-wd010-restore-identity-owner-decision.md 与 RESTORE_IDENTITY_REVIEW.md。此补充取代此前“无法自动识别只能等待”的建议限制。

## A4. 恢复期间的配置页面（已确认目标配置只读）

Owner已选择目标设备配置暂时只读，证据 evidence/20261105-wd010-restore-ui4-owner-decision.md：键位/宏、拨杆、灯光及显示可查看，但不能修改、保存、上传或预览写入；恢复任务的查询/读回/经确认手动重试有专用入口。这样完成后的配置读回不会悄悄覆盖恢复期间新产生的草稿。电脑云端账号窗口、版本信息等无关功能保持可用，不把整个应用遮住。

页面顶部显示原因及“查看进度”：执行中为“设备正在恢复，配置暂不可编辑”；结果未知为“恢复结果尚未确认，配置暂不可编辑”；设备COMPLETE但配置未同步为“设备已恢复，正在同步配置”。固件INCOMPLETE时维持限制，沿已确认界面提供手动恢复。明确拒绝且能确认未开始时不永久锁死；完成并同步后解锁。

此前允许编辑新草稿但禁止写设备的替代方案未获选择，不实施。仅确认只读产品行为，不把它冒充底层锁实现已完成。
当前StudioController与BleManager维护门涉及普通操作和UI回调，不能只新增一个全局禁用状态导致恢复查询/配置读回也被阻断，或永久阻断另一台设备。确切目标锁生命周期、断连后的解锁条件及其他设备行为须进一步设计和验证，不借UI确认扩大实现权限。

## B. 场景与建议处理（下一轮逐项讨论，不一并标批准）

| 情况 | 窗口显示与按钮建议 | 实现约束与需要验证的事实 |
| --- | --- | --- |
| 未连接 | 请先连接要恢复的设备；关闭 | 零恢复写入，不偷偷选择另一台设备 |
| 支持情况未知 | 正在检查设备是否支持；关闭 | 只读探测/已核验固件身份，不用恢复命令探测 |
| 已证实不支持 | 当前固件不支持此恢复操作；关闭 | 区分超时与不支持，不以普通ACK认定支持 |
| 本地正在保存/上传 | 请等待当前操作结束；关闭 | 不自动中止已有任务，不排队自动恢复 |
| 用户取消确认 | 回到原界面 | 草稿保持，零恢复命令 |
| 确认后目标或连接改变 | 设备连接已改变，请重新确认 | 作废旧确认，旧回复不得更新新设备 |
| 已知缺USB供电 | 请为设备连接USB电源；关闭 | BLE连接不等于无外部供电；必须有可靠状态才断言 |
| 固件通用拒绝 | 设备拒绝恢复，请检查供电或是否有其他操作；关闭/重新检查 | 通用result=1不代表已知具体原因，不伪造诊断 |
| 提交中/正在恢复 | 正在恢复，请保持USB供电；关闭窗口 | 禁止同目标重复恢复和配置写入；不显示虚构百分比 |
| 通信超时或断连 | 暂时无法确认恢复结果；重新查询/关闭窗口 | 不显示确定失败或成功，不自动重发；重连同一设备后只查状态 |
| 固件报告INCOMPLETE | 恢复未完成；重新恢复/关闭窗口 | 重新恢复再次确认和检查条件，重新读取attempt；不能使用旧提交自动重试 |
| 固件COMPLETE但配置未读完 | 设备恢复已完成，正在读取配置；关闭窗口 | 不能把配置读回失败说成固件恢复失败 |
| COMPLETE后读回失败 | 设备已恢复，配置读取失败；重新读取/关闭窗口 | 重读配置，不再次执行恢复，不将默认模型填充伪装成真实读回 |
| 完整读回确认 | 恢复完成，已同步设备配置；完成 | 清旧草稿/旧MULTI/旧任务自动重放，保留电脑账号和无关文件 |
| 关闭进度窗口再打开 | 同一任务及当前结果 | 任务不归窗口持有，后台有限频率查询；不重复提交 |
| 退出整个应用再打开 | 查询设备当前恢复状态，区分历史完成与本轮完成 | 不自动恢复；必要任务关联如何持久化待设计，日志不作为固件事实 |
| 设备存储不可用/状态不支持 | 无法安全执行恢复，显示设备返回状态；关闭 | 不开放盲目重试，不转发旧版恢复命令 |

## C. 已定位的真实接入缺口

- TopBar现有入口仅调用StudioState.restoreCurrentModeDefaults，未调用固件恢复。
- K1RouteProtocol.replyLength 当前仅接受version1和子命令0/10/20/21/22；恢复30/31以及v2回复会被拒绝。不能只加一个“发送命令”的按钮。
- BleManager.exchangeK1Route 当前按0x9E等待回复，使用连接generation及K1事务owner；恢复必须遵守现有互斥并匹配version/sub/nonce/attempt，避免K1配置回复与恢复回复串扰。
- UsbHidTransport对0x9E保存k1ReplyRequest并走专门收包边界；USB、BLE都要覆盖17字节恢复回复、拆分/合包和旧ACK拒绝。
- 固件回复result=1是通用拒绝，没有细分供电/忙碌原因；UI不能编造具体故障。
- 数据草稿丢弃时机、连接切换、配置读回覆盖范围、后台查询退避/超时、关闭应用后的关联数据和历史COMPLETE展示，需要在具体设计中收敛，不能凭六项主流程声称已解决。
