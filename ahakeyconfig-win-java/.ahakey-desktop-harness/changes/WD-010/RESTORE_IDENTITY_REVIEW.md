# WD010 恢复目标关联：实现前核对

日期：2026-11-05。只读源码调查，未访问设备；未声称运行时身份验证。

## 已查明事实

- Firmware APP/sub_main/usb1_hid.c 的 MyDevDescr 为18字节，iSerialNumber字段（下标16）是0。当前描述符没有提供USB序列号；不能把OS生成的无序列号实例路径当成独一无二硬件身份。
- Windows firmware/DeviceMaintenanceCoordinator.Identity.samePhysicalDevice 使用container加可选port，否则只比较port。该现有刷机维护判断不能直接授权跨重启恢复任务关联。
- BleManager.FirmwareIdentity 是连接generation、ticket、固件catalogKey，不是设备唯一身份。
- BleManager 的 BLE_STATUS_RESP 注释格式含MAC长度及地址，但当前分支仅解析连接标志和名称，未保存MAC。应从既有桥接协议核对实际字段、长度、地址类型及生命周期，再决定是否能作为同通道关联依据；不能仅因字段存在就保证稳定或跨USB/BLE一致。
- DeviceMaintenanceCoordinator 是全局单活动任务门，RESTORE阶段是刷机后的备份配置回写，允许0x73/0x04/0x8E等写命令，不是工厂恢复。不得复用该服务回写恢复前备份。
- 其正常操作门会阻止Controller普通回调/读回，并可能阻止应用退出。工厂恢复必须有独立查询/读回授权和锁生命周期，不能用现有全局维护锁让结果未知时所有设备永久不可用。

## 无歧义的实现约束

连续连接期间绑定transport、connectionGeneration、选中设备事实；每次回复额外匹配version/sub/nonce/attempt，连接变更撤销原确认。无可靠身份的断连/重启不自动将旧任务绑定到新连接。开始恢复前原子保存最小待核实记录；失败则不发起。发送后本地写失败保留内存只读状态并报告结果待确认，不重新发送。

设备查询与配置读回分开授权；读回必须读取所有受影响且Windows展示的模式/键位/宏/拨杆/K1路由、状态、灯光/显示/资源metadata等，不得用本地默认值充当设备读值。无法读回的字段保持未知并列明，不宣布完整同步。丢弃旧草稿后作废所有旧写队列及自动预览，不能在解锁时补发。

## Owner已确认的产品补充

已确认的自动恢复关联以身份核对成功为条件；当前USB不能保证该条件。建议仅在无法自动确认时提供“确认这是原设备并查询”，显示旧目标信息、当前连接及“请确认连接的是上次恢复的键盘”；用户确认后仅建立人工关联并只读查询，不再次恢复，不把人工确认写成硬件身份验证PASS。仍需匹配原attempt；不匹配时保留旧任务未确认，不能报本次完成。用户不确认则继续保留提示，不自动关联。

Owner已选择“增加人工确认后查询（推荐）”，依据 evidence/20261105-wd010-restore-identity-owner-decision.md。人工关联只用于缺乏可靠自动依据的情况；明确身份不匹配不能人工越过。该选择不改变自动关联的严格要求。未确认、attempt不匹配或本地记录损坏时继续显示未确认，不自动恢复、不报告本次成功。无需修改Firmware或要求Owner提供代码事实。
