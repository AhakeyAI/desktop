## 可执行测试形式

当前仓库没有JUnit/TestFX或src/test基线。本轮拟使用 src/test/java/com/example/ahakey/displayconfig/
中的无新增依赖Java断言入口，显式抛AssertionError并输出用例ID/实际值/非零退出码。
不得只写Java assert而不启用-ea，也不得把mvn test零用例成功算覆盖。

UI用已有JavaFX启动设施和手动操作记录；如需新测试依赖/构建脚本，先追加CHANGE精确路径与批准。
本轮不运行上述命令、不下载依赖。

## Owner Preview建议顺序（后续需绑定实际包）

1. 启动已绑定Preview包，进入OLED；检查三分组、左侧160×80成品、19目标跨Mode映射。
2. 选择一张静态图及合法GIF，检查草稿/帧数；退出重开并删除原图，验证本地成品恢复。
3. 切MULTI核对全局说明；手动刷新不覆盖草稿；设备已有位置显示黑底占位。
4. 准入后确认固定目标并上传；只到设备保存确认才显示已应用。按固件实际状态触发观察，不要求上传即播。
5. 查看灯光，分别预览/保存亮度和某Mode灯效；检查左侧模拟、10秒临时预览和不自动保存。
6. 做一个经Owner同意的上传中断连案例：本地保留失败草稿，重连对账并手动重新上传。
7. 断电重启键盘回读已保存配置；操作原按键/侧拨/Mode/语音进行回归，分别记录USB/BLE实际覆盖。

失败恢复：停止本次写入，不自动烧录/清除设备/恢复出厂；保留本地成品与日志。
需要重连时由用户操作。未确认失败前不宣称旧资源保留；资源INVALID时由固件fallback兜底，
要恢复自定义资源必须重新上传。日志不收录原始个人图片，只记录目标/字节数/CRC/阶段/错误。
正式Owner brief将在具体包和固件准入后补充绝对路径、SHA、启动与逐项反馈，不能使用当前草案当交测包。
