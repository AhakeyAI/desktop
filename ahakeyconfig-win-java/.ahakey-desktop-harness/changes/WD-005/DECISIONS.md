## 本轮技术核实

- 固件19目标、默认8帧/状态12帧、每帧28672字节、Chunk最多48、CRC32、固定100ms。
- 灯光九个AI状态为原有IDEState代码0..8；不是OLED三个状态。
- 固件0x88只回元数据和配置，0x89不支持OFF预览，0x8E逐项保存。
- 旧Windows OLED预览/上传采用raw write+0x82；新CP2不可复用此发送链。
- 旧Windows USB/BLE结束符搜索可能截断含CC DD的CRC；新0x88回复需按类型长度解析。
- 旧waitForResponse会等待重连；CP2必须连接代次绑定和断连立即终止。
- Begin成功确定废弃旧资源；Begin FAIL也可能已转INVALID，不能保证旧资源保留。
  Commit成功但ACK丢失时资源可能有效。错误文案须按阶段表达，回读后更新事实。
- 任一0x8E保存成功会停止固件preview；FAIL不重置剩余时间。ACK无请求ID，超时须隔离会话。

## 真实冲突和非产品阻塞

- 固件支持0x8D不代表Windows要暴露；Owner已定清除仅本地，无冲突。
- 固件的状态回退/预览优先级由固件负责；Windows不能在保存后强制切真实状态，无冲突。
- 旧UI FPS与固件固定时长存在能力差异，由P02收口，不修改固件线协议。
