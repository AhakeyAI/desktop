# WD-005 自动能力准入与灯光禁用反馈增量合同

日期：2026-10-21；DLA。由本轮 Owner 指派授权，须经正式 contract-reconcile 绑定后生效。
沿用J005/J006、high_impact、原起点及现有所有未冲突条款。不是重新立项，不新增固件协议或云端服务。

## 优先级与改变范围

本增量仅替换原合同中“普通用户人工确认指定HEX才能使用CP2”的产品准入方式，并补全灯光分区/禁用状态说明。工程交测的实际HEX核验仍保留。
R6_ISOLATION_INTERFACE_PROPOSAL中的“生产唯一允许改动”指当时隔离修复增量，不限制本轮新增的BleManager身份职责；其测试隔离保护及其他生产行为不变要求继续有效。
旧合同、REFERENCES、批准、报告、审阅、Preview全部原样保留，不覆盖为新语义。

## 产品与工程身份分离

Owner产品策略只有最初旧版和新版 `x1-c582-hw1-p1-1.0.0-r001`。不同WS阶段是同一个新版的开发过程，不要求再分配版本号。
上位机内置精确兼容判断，当前成功识别r001后按本项完成的CP1/CP2能力集开放；不可比较字符串大小、仅判断非空或用“不是旧版”放行未知未来版本。复用AhaKeyProtocol已有精确识别作为小型本地能力规则，不新建通用插件/云端能力框架。
同名中间构建无法从版本字符串区分是已知限制，不用人工点确认掩盖，也不虚构自动读到HEX哈希。
联调仍使用已核对的正常修复HEX：固件根下 `.ahakey-harness/evidence/builds/ws3-cp2-memory-safety-20261018/HID_Keyboard_582m_vibe_coding.hex`，SHA256=FFB9208F79084AA24A832AD2562A14DBBEA5DF4D114A135CB5B2EB98D4E05539；正式CP2 gate为20261018T175441，candidate=70ca334f65d73b6a2f20a0598e55c6da59f26526。此处追加工程身份事实，不改旧REFERENCES，不将CP2.5纳入范围。

## 自动身份状态与服务门禁

1. 区分未连接、读取中、已识别r001、不支持/已确认旧版、未知或读取失败。状态名称可用现有属性/小型嵌套枚举实现，不依赖可见文字作为控制条件。
2. 0x9F读取沿用现有事务队列；串行/去重，可由现有刷新入口重试，不无限后台轮询，不持锁等待FX。
3. 在请求发起、解析缓存、回调及FX提交处校验同一个连接代次/有效读取票据。旧连接迟到回包/失败/FX任务不能准入、清掉或覆盖新连接事实。断连/USB-BLE切换/重连立即使本次准入失效。
4. r001必须来自当前连接成功解析的响应；不从上次本地配置、用户截图、传入任意字符串或V1.x显示文本直接授予权限。移除生产路径上的硬编码HEX人工确认方法/按钮及旧提示，不能改成后台自动调用confirmFirmware(旧SHA)。
5. 保留现有旧版版本显示回退和原协议兼容。0x9F不响应不自动证明是旧版；基础版本仍可显示，但新功能维持未知/读取失败且不可写。若无可靠依据分辨旧版，不伪造LEGACY状态。
6. UI与服务/底层入口共用准入事实。CP1多任务0x98/0x99及CP2的0x88/89/8A/8B/8C/8E须依其现有职责检查能力；legacy SINGLE 0x90及已支持的旧行为不被一刀切禁用。能力识别不等于重连自动保存/上传；保留CP1已有偏好同步边界。
7. 准入成功只解除身份阻塞，不清除未知ACK隔离、busy或上传租约。上传目标冻结、ACK判定、锁顺序、事务互斥、TTL、最新事实补发及连接隔离必须保留。
8. 不为旧设备恢复0x82/raw上传或0x84/85旧全量写入，不改变已过滤写入规则。默认OLED资源的CP2上传同样受准入，不能因叫“默认”就绕过。

## UI行为

顺序固定：运行展示模式（单任务/多任务）→灯光亮度→单任务灯效→多任务任务槽。
“多任务任务槽”明确是最上方“多任务”模式对应的区域，不新增MULTI自定义灯效编辑器；槽位/主槽/灯珠含义和既有绑定行为不改。

- 标题和状态说明放在禁用内容容器之外，保持可读；仅对操作区执行真实disable及辅助浅色。不能只改透明度，不能靠悬停提示才知道原因。
- 模式不符时固定原因：“当前为单任务模式，多任务任务槽不可编辑。”或“当前为多任务模式，单任务灯效不可编辑。”由用户在顶部主动切换；不因点击分区自动发送模式切换。
- 优先呈现实际阻塞原因：未连接/身份读取中/身份失败或不支持，其次上传或保存忙、模式切换中、非当前模式。多原因可合并，但不能只写模式原因掩盖身份/忙状态。
- 建议状态文案：“未连接键盘”“正在读取固件版本…”“固件版本读取失败，请重试”“当前固件不支持此功能”“当前固件版本未识别”“正在上传，请稍候”“正在切换展示模式…”；按真实状态选择，不同阶段保持一致。
- 顶部多任务选择、设备应用按钮，以及OLED SINGLE/MULTI不支持的新设备动作须直观不可用；本地已存资源/绑定不清空，预览仍可查看。旧合同允许的离线本地导入/编辑不因为设备写入能力而扩大禁用，模式相关已有编辑锁保留。标题区域可说明设备应用不可用而本地草稿保留。
- 亮度仍是独立全局区；保存/预览按能力和事务限制，不被SINGLE/MULTI切换错误禁用。
- 同步更新中文/英文资源，禁用说明不可白底白字；不重构全局样式或其他页面。

## 验收增量（保留全部原A01-A11）

- C01：r001当前有效响应无需人工确认即可准入；旧版/空/乱码/未知未来标识/超时不得开放新写入。基础版本显示不丢失。UI与直接服务调用一致。
- C02：断连、重连、USB/BLE切换、旧回包、旧异常和延迟FX任务不能带入准入；当前有效回复不会被旧失败清掉。验证缓存和新写入实际未发生，不只断言generation数值。
- C03：识别不得消除未知ACK隔离；上传/保存/模式/输入回读互斥、取消、锁顺序保持；不因自动准入重传Chunk或自动保存。
- C04：旧版和未知仍保留原有按键、侧拨、语音、模式/版本读取及legacy SINGLE适用路径；新协议受限，不恢复旧raw/全量写入。
- C05：四分区标题、禁用原因与当前模式对应；标题/原因保持可读，鼠标/键盘不能操作禁用控件，正确模式恢复可用；全局亮度不受模式误锁。
- C06：OLED不支持入口明确、原本地资源/绑定/草稿保留；不重新出现白字或乱码。实际UI/高DPI和设备行为留Owner Preview，不以静态断言冒称。
- C07：新增并重跑受影响隔离回归，覆盖两条内存传输分支；先静态确认全部测试无真实USB发现/Socket连接，不覆写整个sendCommand或用假quarantine取巧。
