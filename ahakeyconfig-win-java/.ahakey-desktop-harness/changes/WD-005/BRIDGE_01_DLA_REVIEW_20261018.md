## 实现方向与边界

### B-F1 / P1：新Interlocked调用缺命名空间

TcpServer.cs:333使用Interlocked.Increment；文件只引入System.Threading.Tasks，没有System.Threading或全限定名。当前经典csproj没有隐式全局using，也未见同名类型。Program.cs内的using不作用于另一文件。

这是独立于Windows SDK引用解析的静态编译阻塞，不应把全部构建失败只归于环境。补正确引用/限定名并获得真实编译证据；本轮未运行编译，不编造已观察到的编译错误输出。

### B-F2 / P2：动态分片没有遵守特征200字节上限

Program.cs:347/385将上限设为通用512字节。TcpServer.cs:408直接采用返回值。固件Profile/include/gattprofile.h:46/48的CHAR1/CHAR3均为200，写回调拒绝超长数据。

例如协商MTU247，返回244；一笔大于200字节的WriteData将发出244或201..244字节，旧实现按200分片可接受，新实现会被固件拒绝。当前59字节CP2包不会触发此边界，不把它冒称本次慢上传直接根因；它是改动引入的兼容回归。

分片取实际MTU-3、已验证特征限制及兼容限制的最小值。增加MTU23/62/203/247/517与负载20/59/200/201/多片边界测试；不得用泛用GATT属性最大值代替设备实际限制。

### B-F3 / P1：旧发现回调仍可终止新连接

Program.cs:594的_pendingServiceCount递减及AllCharacteristicsDiscovered发出位于代次判断之外。新连接在:466重设同一个全局计数。Form1.cs:269在收到事件时读取当前代次，而非携带事件所属代次。

可构造时序：A连接发现未完成 -> B连接建立并将计数设1 -> A旧回调迟到，虽然跳过特征列表更新，但仍将B的计数减为0并发完成事件 -> UI捕获B代次，检查通过 -> B尚未找齐特征，Form1.cs:283附近Dispose B。

必须让计数和事件归属发现轮次/连接代次，原始身份一路传到UI，不能在消费时重新贴当前代次。CharacteristicAdded同样检查检查后切换连接的窗口。用受控旧回调晚到测试证明旧轮次不改变新轮次计数/特征/完成/Dispose行为。
