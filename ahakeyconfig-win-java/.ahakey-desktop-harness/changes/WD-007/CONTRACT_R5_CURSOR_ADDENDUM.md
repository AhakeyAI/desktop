# WD-007 R5：Cursor 等待用户操作

Owner 决策见 evidence/20261031-wd007-cursor-waiting-owner.md。此追加说明更新 J015 和 CONTRACT_R4_ADDENDUM.md 中 WAITING 的含义，原合同与 R4 证据不重写。

## 已确认语义

- Cursor 等待用户操作，包括批准请求和等待回答问题，映射 WAITING，沿用现有等待灯效（默认黄）。不强制覆盖用户自定义颜色。
- 运行中仍采用可信运行事件；preToolUse 本身不等于等待。
- 多任务各槽只反映精确绑定会话：A 等待、B 运行时，A 黄、B 保持运行态；不借其他会话事件清除 A 的等待，不更改原槽位布局或协议。

## 最小实现边界

- 读取 Cursor 自身元数据的 hasBlockingPendingActions（本机 3.14.7 实现确认由批准/问答等待合成）。读取必须只读、支持 SQLite WAL 新数据、限时且不阻塞 UI 或设备串行队列；不抓取聊天正文/凭据、不写第三方数据库。
- 先核对精确 conversation/composer 身份及数据来源。重复/冲突、字段缺失、异常格式、读失败、版本/结构不兼容必须区分未知；不能用 false 默认值冒充可信恢复，不能用旧记录或数据库文件整体更新时间伪造当前会话活动。
- 观察和下发必须绑定设备连接代次、实际应用的槽位及状态采样代次；重连、槽位重绑、切换展示模式、应用退出后，旧采样或旧 Hook 不得覆盖新会话。
- WAITING 清除依据新的可信非等待样本或该会话的实际终止/运行事实；必须处理样本与 Hook 竞态、数据库保存延迟及陈旧 true，不能无限保持旧黄灯，也不能把未知直接当运行绿灯。
- 补充元数据观察不改变平台审批，也不改变固件灯光协议、BLE/USB/Hook 已交付修复、单任务模式既有归属规则。

## 验证与交付

- 真实 SQLite/WAL fixture 验证批准/问答共用 WAITING、true/false/unknown、锁定/缺字段/损坏/陈旧/重复来源、关闭后不再轮询。
- 真实运行态服务验证 A 等待/B 运行、只清除对应会话、迟到读/事件、槽位重绑、切断/重连、单多模式切换、终止后残留 true、现有 Codex 等其他平台回归。
- 原生 Cursor 的批准/回答界面与对应元数据 true→false、实际设备灯色必须单独记录。合成事件/内存外设不得冒充真实平台或实机验证；当前没有 Cursor 运行进程，需要时只请求 Owner 做必需的原生操作。
- DIB 实现后原 DLA 实际审阅，保存新的独立审阅与本地模型 Preview EXE 身份；保留已交付 1.0.14，不覆盖旧包或历史失败，未验证不关闭 WD-007。
