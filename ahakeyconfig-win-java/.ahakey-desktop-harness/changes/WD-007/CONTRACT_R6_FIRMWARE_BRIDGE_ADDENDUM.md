# WD-007 R6 三种固件兼容与可见桥恢复

Owner 授权：evidence/20261101-wd007-r6-owner-implementation.md；调查：v1/planned-changes/WD-007/three-firmware-bridge-20261101/CHANGE_INTAKE.md。本补充优先覆盖旧合同冲突的 J011 交互和固件适配规则，保留其他已批准实现及旧证据。

## 固件与能力

- 完整支持 x1-c582-hw1-p1-1.0.1-r001（E75BE8DEF007B7A24502E615C894D68CE454B0FD3A6139AEF45F7C697DEFC233）与 x1-c582-hw2-p1-1.0.1-r001（E19F386D86282E489B595D6D5804F8F43C710429949A2F1C1B9CBCEFCBCF6A29）的已存在对应功能，固定随包离线判断；不规划未来固件自动泛化。
- 无完整可读身份、界面曾显示 v1.0.0 的旧固件，沿原 Windows 已有保存路径和能力分层，不为追求全功能假造新协议；用当前及历史代码核对每个入口。超时/损坏/断连不等于旧协议。通用 ACK 不能赋予 0x97/0x88/0x9E 等扩展能力；只有实际定义响应或已有可信兼容路径才开放。无设备读回时保持原本地配置能力并如实显示结果层级，不把本地值称为设备事实。
- 所有入口统一消费当前会话能力：普通键、K1、拨杆、模式/状态、休眠、灯光、OLED、显示/上传事务与恢复。保留原已验证 CP4C 1.0.0 兼容作为历史回归，不能替代两份 1.0.1 的验收。
- 每次连接、换目标及断开使上一设备身份/能力失效，读当前身份/状态再开放相应入口。不得以持久化设备名称、上次能力或过时白名单阻断正式固件。

## 桥交互与单目标

- 主软件启动显示可操作蓝牙桥窗口，设备列表、连接过程和失败原因可见；保存上次 BLE 名称和地址，下次启动自动尝试，保留手动选择。名称不是身份，不自动续传旧任务。
- 保留托盘，桥窗口关闭仅隐藏。BLE 驱动普通点击启动未运行的所属桥或唤起已运行桥窗口，不重启正常连接。主软件菜单退出仍有界停止所属桥，主窗口 X 沿原托盘规则。
- USB 优先，不让桥自动重连抢占 USB；USB 正在配置时桥窗口可关闭。拔 USB 后保持断开，抑制后台 BLE 自动接管；点击 BLE 驱动打开桥再由用户手动连接。
- 界面选择必须进入现有连接协调与取消流程，桥和主软件只能共用一个实际配置目标；不能并行启动旧 Form 的独立 TCP/设备会话。保留多 USB 选择、旧草稿隔离、上传 A 切 B 取消及不向 B 续传规则。
- 重连身份/状态/恢复核对失败显示明确错误并可重试，不能发布假可用。解绑旧会话后断开事件必须到达 UI 并停止轮询；旧业务完成与旧通知仍不能影响新目标。

## 恢复与保留

- 不直接删除 device-recovery.json 或持久化未确认记录。中断后的当前键盘实际状态核对成功才恢复操作；失败保留原因和重试路径。版本准入不能永久锁住两个正式固件。
- 传输沿已追踪源码输入+scripts/ble-driver-fixes.patch+ManagedBridge.cs：保留串行发送、正确分片、CCCD确认、完整回包、取消/超时、session/instance/generation隔离。main-anpx 22e49fb 只借鉴窗口/保存目标/托盘交互，不整文件回退传输。
- 不改/烧录 Firmware，不改语音、Hook、Cursor、OTA信任、安装路径规则、用户宏/图片资料。允许发行版本推进至 1.0.16，同一应用安装身份，沿现有完整 local-model 配方。
