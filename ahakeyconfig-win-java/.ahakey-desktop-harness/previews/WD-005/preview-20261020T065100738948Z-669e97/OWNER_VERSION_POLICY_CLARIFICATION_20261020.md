# Owner 固件版本策略澄清

来源：2026-10-20 原 DLA 当前对话。追加澄清，不覆盖上次调查或冻结合同。

Owner 明确：多个 WS 阶段是在持续完善同一个 `x1-c582-hw1-p1-1.0.0-r001` 固件版本；最初完全没有 WS 修改的版本为旧版，Owner 记忆其显示为 V1.0.0。当前产品面向用户只区分最初旧版与新版 r001，不要求按 WS 阶段再分配版本号。

据此撤回上一份提案中“必须新增固件版本标识才能继续”的前置建议。保留静态事实：同一 r001 的历史开发构建不能仅凭标识区分功能完成度；这属于联调产物身份约束，不自动变成新增产品版本的要求。

后续合同修订采用本地两代兼容策略：
- 成功读到精确 r001 时，按本次已完成的新固件能力集准入；不要求普通用户人工确认 HEX。
- 已确认的最初旧版保留原有行为，禁用不支持的新设备功能；不清除本地资源或会话绑定。
- 断连、身份读取中、读取失败、未知标识须与已确认旧版区分，不能用“未读到r001”笼统证明是旧版或直接放行新写入。
- 不根据版本字符串大小推断未知未来固件兼容，不引入云端。
- 工程测试仍核对实际修复版 HEX，历史中间 r001 构建不能因同名就被宣称具有完整新功能或已修复。
- 灯光分区命名及明确禁用原因的修正继续有效，无需重复询问产品设计。

只读核对 DeviceStatus.getDisplayFirmwareVersion：有 catalog key 时显示该字符串；没有时若主/次版本有效则显示 `V<main>.<sub>`，否则 `-`。因此当前这段代码不能证实精确文案为 V1.0.0；这是显示回退，不是给设备回刷/降级固件。实际旧设备兼容分支需在实施时沿调用链保留与测试。

此记录是 Owner 语义澄清，不手写正式路由或新实现批准回执。本轮未修改生产/测试/固件/桥接，未构建、启动、Git写入或操作设备。后续 DLA 按 Harness 协调当前人工确认契约到自动能力准入，再交 DIB 实施。
