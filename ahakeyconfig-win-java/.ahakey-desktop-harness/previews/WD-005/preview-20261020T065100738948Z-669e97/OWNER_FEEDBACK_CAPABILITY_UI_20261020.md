## Owner 已报告正常的范围

- OLED 卡片文字、资源名、帧数清晰，中文日志正常。
- 灯光区域顺序、非当前模式浅色处理、OLED 多任务入口提示正常。
- 本地选择图片/GIF后的名称、帧数和预览正常。

Owner 同时明确：浅色处理虽然出现，但不能直观传达不可编辑及原因；曾反复点击按钮而疑惑。不能把上一项“正常”扩大为禁用可理解性已通过。
本反馈不证明上传、设备保存、真实灯光、全部验收、BLE性能或507项以外的新执行。

## Owner 新要求

1. 实际产品去掉“确认配对固件”手动入口，自动读取设备固件版本，决定新功能是否可用。
2. 不支持的固件不能使用灯光 MULTI、OLED SINGLE/MULTI 等新功能。
3. 明确最后的任务槽区域属于顶部“多任务”模式；明确单任务灯效与多任务任务槽各自的关系。
4. 禁用不能仅降低透明度，需要让用户一眼理解为什么不能编辑。

第一项改变当前“人工确认精确HEX”的准入契约，应按合同修订处理，不伪装为简单删除按钮的实现Bug。UI可理解性按既有功能修正，不重开已确认的分区顺序。

## 建议边界，待关键身份方案确认

- 固件为可区分的功能/兼容性版本提供新的正式catalog key或等效可读取能力标识；Windows本地维护精确标识到能力集的映射。不凭字符串“较大”或“非旧版”解锁，不要求云端。
- CP1多任务运行展示与CP2资源/灯光配置分别判断，不把所有旧固件视为完全无功能；保护WS001-004原行为与本地草稿。
- 每次连接/重连重新读取、绑定连接代次；未知/读取失败不允许新设备写入，允许重试并解释原因，不用旧设备的识别结果。
- 去掉面向普通用户的HEX确认按钮；发布/交测记录仍保留精确固件产物身份，产品能力识别不能代替工程验收身份。
- UI分区统一为“运行展示模式”“灯光亮度”“单任务灯效”“多任务任务槽”。
- 标题和禁用原因保持可读，只禁用对应操作区。单任务时明确“当前为单任务模式，多任务任务槽不可编辑”；反向同理。不因进入分区自动切换模式。
- 未连接、读取中、不支持、上传忙、模式切换中分别表达原因；不把全部原因伪装为“非当前模式”。
- 不支持固件下保留可见入口和说明的方案优先，不清空既有本地绑定/资源；具体本地编辑保留既有合同，设备写入严格门禁。
