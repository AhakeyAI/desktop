## Colors

Blue is the single action and selection accent. Neutral surfaces separate navigation, header, working area, panels, and feedback.

- **Primary:** `Accent` and `OnAccent` define the primary action; the selected transport uses `Selection` fill with an `Accent` border; `Focus` identifies keyboard focus and selected-status text. Focus is theme-specific while action blue is shared.
- **Neutral:** `AppBackground` is the canvas; `Surface` is navigation, header, controls, and panels; `SurfaceRaised` supports feedback, display placeholders, and disabled buttons. `Border`, `TextPrimary`, and `TextSecondary` retain semantic roles in both themes.
- **State:** `Selection` fills current navigation and highlighted menu items. `ProfileSelection` gives profile cards a quieter tint; `IconSurface` supports their icons. `HardwareCanvas`, `Screen`, and `ScreenText` define hardware preview surfaces. `Warning` identifies simulation and backend limitations; `Danger` identifies errors. `Success` remains an available theme resource. `Disabled` supports disabled labels and scrollbar thumbs.
- **Physical-key overlays:** `KeySelection` and `KeyHover` place translucent blue over the photograph, leaving the physical key visible. Selected keys use an `Accent` outline; hover uses `Focus`; keyboard focus adds an `OnAccent` inner ring. The frontmatter expresses these alpha colors in CSS RGBA hex order; WPF stores the same channels in ARGB order.

**The Semantic Resource Rule.** Bind themed brushes through `DynamicResource`; keep brush values in the two theme dictionaries. Shared Expander and CheckBox styles bind `Foreground` to `TextPrimary`, including Settings Developer mode and Diagnostics Advanced. System selects a supported theme rather than defining a third palette.

**The Written Status Rule.** Pair state color with localized text. Distinguish connection, synchronization, and settings or operation errors.

## Typography

Segoe UI is the window-level family, with Windows font fallback for CJK. Consolas is reserved for diagnostics. Use the semantic PageTitle (28), SectionTitle (18), CardTitle (17), Body (14), Secondary (14), and Caption (12) styles. BrandTitle (16) and TechnicalText (12, Consolas) cover specialized roles. TechnicalText lives in Controls.xaml and inherits the themed TextBox style, including its surface, text, caret, selection, and focus treatment. Ordinary page text uses these semantic styles. The physical Key Test capture field has a local 20 DIP size for the observed shortcut; it is not a new shared type token. Display state headings use CardTitle.

Text wraps by default; secondary copy has an explicit line height. Preserve readable EN/RU/ZH labels and explanations when resizing. Retain wrapping rather than introducing truncation, uppercase transformations, or decorative display fonts.

## Do's and Don'ts

- **Do** preserve the fixed sidebar, persistent profile/connection header, two-column profile grid, and vertical scrolling.
- **Do** use semantic theme resources and localization bindings for new native controls and copy.
- **Do** retain written simulation, real read-only, local-draft, unknown-contract, stale-observation, selection, and error states alongside color.
- **Do** keep normal Real startup and the Connect entry point clear, and place Mock selection under Advanced / Developer mode.
- **Do** keep USB identification separate from explicit connection, use neutral USB identity, and disable Connect/Reconnect unless one safe HID candidate is identified.
- **Do** use Display / Animations and color IPS in user-facing copy; retain the legacy serialized `Oled` key only for local-draft compatibility.
- **Do** use the shared freshness snapshot for body and header; omit stale header battery without changing connection status.
- **Do** keep the four physical-key selection regions aligned to the supplied photograph and pair blue selection with a distinct keyboard-focus ring.
- **Do** keep integration evidence independent, show concrete owned changes before Apply, and retain keyboard focus and the open review through status updates.
- **Do** preserve explicit service startup or its saved opt-in, native trust, metadata-only history, and session-only hardware AUTO initially off.
- **Don't** imply simulated read/write evidence represents a physical device operation.
- **Don't** present a Bluetooth or USB connection or telemetry sample as configuration readback, Synced, or a verified capability contract when fields are absent.
- **Do** keep exact selected-key review, ACK acceptance, focused behavior observation and absent readback distinct; preserve K1 and the global-save warning.
- **Do** show current feedback failure ahead of a historical preview result and explain reconnect or off/on recovery while retaining the saved preference.
- **Don't** extend physical RGB acceptance beyond separately command-tested and user-observed 01/00 on each exact accepted USB or BLE identity and firmware; USB proof never grants BLE acceptance, and ACKs or offline images alone remain insufficient.
- **Don't** add full-profile writes/readback, injected physical Test, brightness setters, firmware operations/probes, GIF uploads or other physical Display targets. Accepted selected-key, RGB and exact-scope static Display controls use separate gates; normal physical reads remain `00`/`9F`, and approval refresh uses only `00`.
- **Do** keep static upload inert until the attested capability and exact overwrite confirmation; disclose destroyed pixels, unknown aliases and global save, and distinguish metadata success from user-observed image acceptance.
- **Don't** replace native WPF controls with web approximations or apply HTML/CSS detectors to this application.
- **Don't** treat screenshot review as hardware, actual monitor DPI, Windows high-contrast, or screen-reader acceptance; those require separate evidence.
