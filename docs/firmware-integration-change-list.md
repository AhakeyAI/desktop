## 分支更新与使用限制

下文缺口最初按 `d1b46a14` 审查。2026-10-19 GitHub API 复核 `Fireware-harness` 分支头已到 `70ca334f65d73b6a2f20a0598e55c6da59f26526`，新增 WS3 展示、资源/显示事务与内存修复。抽查仍有 K1 Consumer `0x00CF`、`0x87`、`0x96`，catalog key 仍与旧基线相同；工程状态记录为 CP1 accepted、CP2 active。因此需先逐项说明新代码已覆盖什么、尚缺什么、哪些已验收，再安排增量实现。不能根据 catalog 相同认定能力相同，也不能把本清单全部当成尚不存在的代码。

本轮不要求接管或重做其他固件工作流，不自动开放尚未验收的 WS3/WS4/WS5 能力。确切提交、构建配置和 HEX 哈希必须绑定交付。

## 基线与已确认的产品行为

- 原已审查固件基线是 `AhaKey-X1-hardware-source/Fireware-harness` 提交 `d1b46a14a796790f2ffe0d228e6c5badcfc34d75`，`0x9F` catalog key `x1-c582-hw1-p1-1.0.0-r001`；最新分支差异按上节复核后再固定实施基线。不要与 Rust 联调手册的 `eternal-dev` 1.4.8 / 协议 3.2 候选混用。
- 当前 Mac onboarding 完成后，Voice/K1 优先发 Consumer Usage Page `0x0C`、Usage `0x00CF`；普通绑定中的 F18 不代表当下实际事件。
- macOS 正式版默认保留 Consumer Voice；Studio 允许用户随时在“系统 Consumer Voice”和“AhaType”之间切换并切回。Windows 保留现行 Ctrl+Win 默认，本轮不展开 Windows 语音设计。AhaType 由电脑端转写与文本整理，固件不承担云端处理。
- 用户在 Studio 选择 AhaType 时，只有 Runtime 后台录音与云端音频转写链路、麦克风权限及 AhaType 账号登录鉴权均就绪，才切换固件路由；未就绪时保持 Consumer Voice，Studio 显示原因并引导完成设置。用户选择与当前实际路由须分别表达。
- AhaType 被选中后，Runtime 关闭、故障或不可用时，Mac Voice 自动回退 Consumer Voice；Runtime 恢复且语音链路就绪后回到用户选择的 AhaType。Runtime 意外崩溃由后台管理程序自动尝试重启，恢复期间保持 Consumer Voice；Studio 主动关闭 Runtime 则保持关闭至下次打开 Studio。电脑重启而未打开 Studio 时不主动启动 Runtime，正常退出 Studio 后已运行的 Runtime 保持运行。一次按键只触发一条链路。Windows 回退细节留待其独立发布线讨论。
- 用户接受完整语音能力需要升级现有键盘固件。用户确认当前硬件**关机状态下长按 Voice/麦克风键即可进入 BOOT**，无需拆机；正式发布前仍需完成升级镜像、刷写工具、失败恢复与真机验证，不能只凭 BOOT 入口宣称升级流程已闭环。
- 用户在 Studio 内点击升级并按提示操作实体键盘；Studio 执行受控刷写指令和结果确认。用户不需要安装或操作另一款刷写软件。
- 固件升级必须保留并在升级后核验已有键位、宏、灯效、OLED 图片和语音选择；若某台设备无法可靠保留或备份，Studio 须在刷写前阻止升级并解释。现有 `0x87` 单键读回不能充当全部资源的备份证明，OLED 等资源的保留机制和验证方法仍需固件侧给出。
- 若刷写断电或断线后设备只剩 BOOT，Studio 应能识别并以已校验镜像引导重刷和核验。只在真机证明可恢复原镜像时宣称“一键回滚”；从 BOOT 重刷是最低可接受恢复路径。
- 2026-10-14 用户取消普通 F5 语音机制。系统语音默认保留 Consumer Voice；F5 不进入本轮固件改动或验收。

## 已知固件缺口与改动需求

1. **可逆 Voice 路由。** 已审查基线的 `0x96` 只允许写入 `suppressed_by_desktop`，不能由同一命令恢复 `completed_mac`；该状态还与 Mac Consumer 特殊分支耦合。固件需提供可验证、可逆的路由选择，使 Mac Consumer 模式和电脑端 AhaType 触发模式能反复切换，不因重连或配置写入意外覆盖用户普通绑定。具体命令编号、状态持久化及与 onboarding 的分工待固件侧设计。
2. **Runtime 失联回退。** AhaType 模式须有设备侧可判定的短期 host 有效性；超时、断连、Runtime 崩溃和 Studio 手动关闭后自动恢复 Mac Consumer Voice。Runtime 恢复且录音、云端转写、麦克风权限和 AhaType 鉴权均就绪后，才重新宣告用户所选模式；不能仅凭进程启动或连接恢复即切回 AhaType。后台自动重启属于 host 管理职责，须区分意外崩溃与用户主动关闭，固件仅依据有效的 host ready 状态执行路由。超时值、心跳机制和按住期间切换规则待联调冻结；不得依赖 Studio 进程一定存活。
3. **无双触发的 AhaType 事件。** 现有 Consumer 事件会由 macOS 处理；仅在 host 侧被动监听不能保证阻止系统语音同时启动。AhaType 路由应发与 Consumer 区分、可由 Runtime 可靠识别的触发事件，或提供其他经 macOS 真机验证的互斥机制。F18 可作为候选，非预设的唯一协议答案。Runtime 要支持短按切换录音、长按按住/松开结束；固件事件须能可靠表达 USB/BLE down/up 和时序，一次按压不能双触发。读写、切模式、断线和路由切换时不得产生卡键或重复开始录音；可用既有机制证明时无需再造一套手势协议。
4. **能力发现与读回。** 固件身份/能力响应应能区分支持新 Voice 路由的构建；Runtime/Studio 应可读取有效路由及 host 有效性，准确显示“用户选择”“设备当前执行”“回退原因”。不能仅凭普通键 `0x87` 读回推断 Consumer 特殊分支已停用。旧固件应明确报告不支持切换，不发送未知命令。
5. **升级与恢复。** 固件侧须提供可交付镜像、版本/能力标识、升级前后完整配置保留或备份/迁移规则、失败恢复与回退说明，并给出 OLED 等不可由 `0x87` 覆盖的资源如何核验。进入 BOOT 的用户操作按“关机后长按 Voice 键”验证，不要求拆机；Studio 负责调用受控刷写工具并确认结果。若无法可靠保留现有设置，则刷写前拒绝；不能靠事后提示弥补。中断后若只剩 BOOT，须能从 Studio 继续刷入已校验镜像并验证结果；不宣称未验证的原镜像回滚。与客户端共同验证旧 Consumer 设备升级后仍可直接用 Voice、用户已改普通键不会被静默重置。

6. **完整设备配置读回/导出。** Studio 连接后优先读设备，经用户确认后同步展示全部设备可编辑项：键位/宏、灯效、亮度、拨杆设置和 OLED 当前画面。现有 `0x87` 单键读回不足；固件侧需补齐可校验的读回/导出能力与能力标识。每个允许逐项写入的项目还须能在 ACK 丢失后独立读回并与目标值比较：相同即成功，不同才自动重试。无法读回的项必须明确标“未读取”，不得用本地草稿伪装；OLED 不要求还原原始 GIF 文件，但必须能呈现设备实际画面。读取期间的一致性和断线/部分读取语义需要设计。
7. **Windows 预设保留（本轮不施工）。** 已核对 `Fireware-harness` 提交 `d1b46a14`：`main.c` 的 `voice_preset_windows_wechat[] = {0x73, 2, 0xe0, 0xe3}`，Windows onboarding 完成时写入 K1 的前 `USER_MODE_COUNT - 1` 个模式；`psk_multi_button.c` 发送 `0xe0` 左 Ctrl + `0xe3` 左 GUI/Win，未包含 H (`0x0b`)。用户于 2026-10-15 明确保留现行 Ctrl+Win 默认，重点先放 macOS；先前 Win+H 默认提议撤回。Windows 回退、安装和验收另在其独立发布线处理，不作为本轮固件改动要求。官网 Windows PDF 与当前固件行为及微软内置麦克风说明不一致，后续维护 Windows 文档时需修正。

## 联合验收门槛

- Consumer 默认：无 Studio、无 Runtime 时，真实 USB/BLE Voice 事件与系统行为符合当前已验收路径。
- 用户切换：Consumer → AhaType → Consumer 可反复执行，设备读回与实发事件一致，一次按键只启动一条语音链路。麦克风权限、AhaType 账号鉴权或云端转写链路任一未就绪时保持 Consumer；全部就绪后才进入 AhaType。
- 故障回退：Studio 退出但 Runtime 仍运行时按用户选择工作；Studio 手动关闭 Runtime、Runtime 崩溃、BLE 断开或 host 失联后回退 Consumer；Runtime 意外崩溃可自动重启，重启就绪前保持 Consumer，就绪后回到用户选择；Studio 主动关闭后保持关闭至下次打开 Studio。
