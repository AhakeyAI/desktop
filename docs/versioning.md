# AhaKey 界面开发 · 版本怎么管（小白版）

用三句话记住：

1. **写界面代码** → 在 `ui/develop` 分支  
2. **做完一小批能给人用的改动** → 更新 `CHANGELOG.md`，打一个版本号标签（如 `v0.2.1`）  
3. **正式告诉别人有新版** → 在 GitHub 的 Releases 里写几句更新说明  

---

## 我该看哪个分支？

| 名字 | 是干什么的 | 你日常要不要动 |
|------|------------|----------------|
| `ui/develop` | **界面开发主线**（最新 UI 在这里） | ✅ 日常在这里改、推送 |
| `main` | 仓库默认主分支（偏整仓/上游历史） | ⚠️ 暂时先别往这里硬合 UI，避免搞乱 |
| `feat/xxx` | 临时功能分支（可选） | 做完合回 `ui/develop` 后可删 |

以前的 `integrate/keke-vibebar-ui` 已经改名为 **`ui/develop`**，内容一样，只是名字更好记。

## 版本号怎么起？

只使用这种格式：

```text
v主版本.次版本.修订号
例如：v0.2.0、v0.2.1、v0.3.0
```

简单约定（界面相关）：

- **修订号 +1**（`v0.2.0` → `v0.2.1`）：修 bug、小样式、小文案  
- **次版本 +1**（`v0.2.0` → `v0.3.0`）：一整块新功能（比如新的设置页、大改布局）  
- **主版本 +1**：很少用；产品形态大变时再考虑  

**不要**再用这种标签：日期名、随便起的英文名、带 `#` 的名字。那些不算正式版本。

## 发一版时按这个清单做

1. 确认改动都在 `ui/develop`，并且已经 `git push` 到 GitHub  
2. 打开根目录的 `CHANGELOG.md`，在最上面加一节「这次改了什么」  
3. 打标签（例子：下一版是 `v0.2.1`）：

```bash
git tag -a v0.2.1 -m "简短说明这次版本"
git push origin v0.2.1
```

4. 到 GitHub → **Releases** → 选这个标签 → 写几条用户能看懂的更新说明  

打 `v*` 标签后，仓库里的自动流程可能会帮你打 macOS 安装包；有的话会出现在 Release 附件里。

## 两个远程是什么意思？（了解即可）

| 远程名 | 地址 | 你怎么用 |
|--------|------|----------|
| `origin` | 你的库 `bukeke111/desktop` | ✅ 平时只推这里 |
| `upstream` | 组织库 `AhakeyAI/desktop` | 需要同步别人进度时再拉，不要随便推 |

## 常见担心

**Q：我改错分支了怎么办？**  
先别慌。看左下角/终端里当前分支是不是 `ui/develop`。不是的话先切回去再提交。

**Q：标签打错了怎么办？**  
告诉会用 git 的人帮你改；小白阶段宁可多问一句，也不要连续强推删除。

**Q：旧分支 `my-branch`、`vibebar1.0` 还在？**  
先留着当备份，不删也不继续往上堆新功能。新工作只走 `ui/develop`。
