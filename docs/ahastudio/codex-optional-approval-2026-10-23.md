# Codex 可选审批与原链路回退

2026-10-23，用户明确修订 H02-CODEX-LIVE：拿不到 AhaKey 自动授权不等于拒绝，必须继续 Codex 原链路，该请求批准就请求，该自动执行就执行。

## 原因与修复

旧 PreToolUse 把完全访问和未知模式当作需要键盘重新授权的会话；手动、离线、暂停或证明不完整时返回 deny。SessionStart、PermissionRequest、安装 Hook 还会自动改写默认审批策略。这会阻断用户正常操作，不能靠返回 ask 修复。

- 所有 PreToolUse 仅同步任务状态，返回空对象；不额外查询授权、不输出 deny、不改用户策略。
- 真正的 PermissionRequest 仅在实时自动档证明有效且本客户端管理未暂停时返回 allow；否则不返回审批决定，由 Codex 继续原流程。
- Hook 安装、会话开始与每次审批均不写默认权限。有效的用户 never／完全访问选择保留。历史拥有租约和已废弃无效配置的兼容清理仍限定在旧配置迁移中。
- 实体切到自动档时，在 Studio 底部录音胶囊提供“设置请求批准／保留当前权限”。不弹阻塞对话框。录音和处理期间延后提示，不打开麦克风、不抢焦点。
- 只有用户确认设置才调用保留其他 TOML 字节的 on-request 写入接口；失败不记为成功。保留当前权限零写入，不反复提示；拨杆编辑区可重新打开提示。
- 设置的是后续会话的默认值，不能承诺改变现有 GUI 完全访问会话。提示要求在 Codex 中切换当前权限，或新建使用请求批准的会话。

## 回归要求

真实 Handler 注入 IO 覆盖手动、离线、未知、暂停、大输入与完全访问；确认仅一次任务状态请求且输出无决定。原生 PermissionRequest 的无授权必须无 allow／deny。选择模型验证展示／拒绝零配置写入，接受仅一次，失败可重试。

真实 Codex CLI 使用临时 CODEX_HOME、生产输出模块和本地 Responses 夹具分别验证同一会话五个状态：原生审批自动／恢复自动执行，其余由原生请求确认；完全访问五个状态均继续执行且保持 never。无需账号和外部服务，夹具不冒充实体 BLE 端到端验证。

## 屏幕编辑的并行工作

按已确认原型 A 整合“屏幕画面”：展示方式、图片与动图、当前任务分区；图片以单任务／多任务平铺状态卡选择。底部唯一写入入口提交当前模式四个位置、共享多任务三个位置和展示／跟随设置；保留其他模式草稿。刷新无写入、断线目标核验、部分完成不伪装回滚。此功能与审批回退分别验收。
