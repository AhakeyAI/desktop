# 当前保存值与历史模板迁移分离

WBS I01/I02a/L02，已实现并安装build572/sourcec6bd5ad1。

## 已复现的问题

当前版本用户把Claude No从宏改为普通Enter，Store保存后再加载会恢复成出厂宏；DIY Key4明确设为Enter也会变回Backspace；保存50%亮度会被迁成35%。同样的旧模板判断同时作用于草稿及已确认基线，可能改变用户选择或同步判断。生产Store＋隔离UserDefaults反馈环在3项测试出现6个失败断言；没有修改Owner偏好或真实键位来复现。

## 处理

Store保存草稿或确认基线时，在原JSON根级增加`legacyTemplateMigrationVersion:1`，`modes`仍处于原层级。带标记的当前保存值不再运行历史模板升级；无标记旧数据保留原升级逻辑，应用按正常保存流程写入标记。未提高固件协议要求，不写键盘，也不把未确认草稿当作确认基线。

将每次启动仍需运行的上传中断提示/待重传恢复及内置素材路径修复抽为独立步骤，旧数据迁移及当前数据加载均调用；用户外部素材路径保留。缺失模式补全的原逻辑保留。

## 证据和边界

11项迁移测试及1058项全量通过，包括重复保存加载、草稿/确认基线、普通键/宏/亮度、当前格式上传中断恢复、无标记旧数据迁移、旧Draft解码器读取新增根字段。[源码CI三项](https://github.com/AhakeyAI/desktop/actions/runs/42152594498)成功，双架构签名候选已安装；连续两次原生启动后15项设置内容均与安装前相同，只新增内部标记，后台连接恢复。

旧解码器能读取新增字段不等于旧应用会尊重新标记：降级至旧实现后仍可能执行其历史迁移。本轮没有改变无标记旧数据的既有迁移判定，也不宣称已覆盖所有损坏/未来格式、旧设备及真实HID完整矩阵。固件Issue11宏后Enter持续按住与本次本地存储问题分开，仍未修复。
