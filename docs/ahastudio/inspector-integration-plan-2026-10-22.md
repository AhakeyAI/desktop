# 新固件设置整合回虚拟键盘右侧编辑器

日期：2026-10-22。核对基线：connect&talk / b0ce2ea（已合入PR152）。
状态：终版v1，用户已逐项确认并确认整体定稿。
本轮仅完成方案，不修改App代码、不写键盘、不覆盖本机候选。

## 产品要求

唯一用户主链路：选中虚拟键盘的组件 → 右侧查看 → 修改 → 原位编辑与保存 → 返回日常连接。
取消“更多 → 键盘设置…”及六标签独立设置面板，不将其保留为另一套用户配置入口。确认上传覆盖等单次确认框可以保留，不再跳到另一个配置页。

## 代码事实与问题

1. `Sources/Views/AhaKeyStudioView.swift` 的 `inspectorPane` 已有390pt右侧摘要/修改/返回/保存。`enterEditingConfiguration` 让App临时接管蓝牙；浏览模式标签只改selectedMode。
2. 同文件的 `KeyboardSettingsRequest`、sheet和`openKeyboardSettings` 新建独立页；`performUnifiedDeviceWrite` 对非legacy固件跳到该页，`finishEditingConfiguration` 也跳转。普通键由画布提案再经“读当前→载入画布草稿→应用”二次编辑；并非仅调试。
3. `KeyboardSettingsView.swift` 六标签包括按键、工作模式、待机、拨杆、语音、显示。打开入口和保存主链路都指向它；关闭又交还Agent。
4. `DeviceInfoView.swift` 还嵌入Standby/SideSwitch/OrdinaryKey/Voice四个编辑器，形成第三处可写入口。
5. `oledInspector` 仍有旧分区、70帧和1–30FPS，另加按钮跳新素材页；新WS3实际上19位置、按位置8/12帧、固定10FPS。
6. `lightBarInspector` 仍是旧0x84/85/91文案、按模式亮度草稿；新WS3使用全局亮度及0x89/8E窄事务。旧预览按钮对新固件禁用，形成能改草稿但不能直接保存的割裂。
7. `dirtyCount` / `lastSyncedDraft` 基于本地整份草稿比较，不是设备事实。只有普通键确认通知和Voice接管已有部分回写，WS3素材/灯效与画布摘要未统一。`studioDraft.onChange`还会更新本机语音路由，迁移中必须区分本机配置与设备接管。
8. 新设置页承载的不只是布局：含读回授权、基线冲突检查、连接代次、取消、ACK/读回、逐位置未确认反馈。不能删页后直接恢复旧全量写入。

| 用户位置 | 整合内容 | 保存范围 |
| --- | --- | --- |
| 选Key2/3/4 → 右侧修改 | 沿用组合键/宏/描述编辑，设备当前值在同处展示；移除第二套模式/键号选择与“载入草稿”步骤 | 当前选中模式的这一键 |
| 选Key1 → 右侧修改 | 当前模式独立的Consumer/App原生转写/AhaType/自定义快捷键及权限；Consumer混用需固件合同核验 | 保存当前模式Key1；禁止隐式重写其他模式Voice |
| 选灯条 → 右侧修改 | 当前模式九状态灯效、全局亮度、预览与停止；全部36项总览作为可展开只读区 | 指定状态灯效或明确列出的修改项；亮度单独保存 |
| 选屏幕 → 右侧修改 | 模式默认/进行中/等待/完成素材；多任务三位置在高级区，合计覆盖19位置；图片/GIF选择、预览、容量、进度、核对、恢复 | 当前明确位置，上传覆盖/恢复分别确认 |
| 选拨杆 → 右侧 | 实体位置与审批有效性展示，不提供软件切档；保留默认收起的高级绑定编辑区 | 两位置绑定按现有协议明确确认，不改变实体档位 |
| 现有模式区 | 浏览配置与“切换键盘到此模式”分开，原位显示确认结果 | 只切工作模式，不保存其他配置 |
| 现有设备信息 | 保留电量/连接/版本/诊断，以及设备级待机选项 | 待机单项；移除重复的按键/拨杆/Voice编辑 |
| 屏幕/灯条查看态 | 多任务概览与单/多任务显示选择，保持Agent归属 | 运行中的显示请求，不能因浏览自动应用或记作持久配置 |

灯效九行可各有保存动作；若提供底部“保存修改”，必须先生成可核对的变更列表并逐项串行执行。全局亮度必须单独标明影响四个模式；逐模式Voice不能借此隐式改全局策略或其他模式。资源上传独立于普通配置保存，不因其他组件保存附带上传。

## 统一交互

1. 选中组件只浏览，不发保存命令，不抢Agent连接。
2. 点击“修改”时固定目标（设备、浏览模式、组件、子位置），仅在必要读取期间App取得配置连接，查询结束交还Agent；保存或明确预览时再临时取得连接；同目标/同代次合并重复读取。WS3仍需现有完整19项proof后才开放写入，不能以局部读取绕过授权。交还Agent后设备事实不再具有当前连接的写入授权；再次取得连接必须重新取得proof，编辑草稿独立保留。
3. 展示“键盘当前”与编辑草稿。首次无草稿时由已确认设备值初始化；已有草稿不静默覆盖。设备值变化时提示冲突，不自动写回。
4. 用户在原有编辑器修改，底部直接“保存此键/保存灯效/上传此素材”等具体动作，不再弹出第二套设置页。非法输入原位提示，不截断/过滤成另一个值后写入。
5. 保存内部执行既有基线校验、窄命令和读回。成功更新对应摘要和该目标的已确认基线，其他草稿继续待保存。提示区分已读回与已验证断电保持。
6. 返回结束本次编辑并交还Agent；未保存草稿保留，但不重放。失败、中断、部分成功分别保留；恢复连接后重新读事实，禁止旧回包更新新目标。
7. 写入期间禁止切目标；提供当前操作的取消。取消可能已写入，不声称回滚。正常浏览切换可保留每目标草稿。实体模式变化仅更新实际模式标识，不悄悄重定向正在编辑/保存的目标。
8. 单/多任务运行模式仍经Agent请求，放在查看态，避免和App素材编辑抢蓝牙。进入编辑前的运行状态不做隐式重放。

## Module与状态设计

保留 `AhaKeyBLEManager`、Shared的Confirmed事务、配置命令门控及串行通道；不重新写一套协议，也不加Runtime依赖。

在现有Inspector与这些事务之间放一个编辑会话Module（拟名 `StudioInspectorSession`），Interface只面向当前目标：开始编辑、更新草稿、提交明确变更、取消、结束。将连接归属、查询准备、代次票据与结果归并放在其Implementation中，View不再自行安排交接及多个Task顺序。

状态至少包括：
- 固定目标：设备身份＋配置模式＋组件＋子位置；和实时workMode分开。
- 设备事实及generation、每目标草稿、每字段确认结果与未知值。
- 阶段：连接中、读取中、可编辑、保存中、已读回、未确认/冲突。
- 操作ticket、目标版本、受影响位置及取消状态。

普通键/Voice/灯效/素材使用各自现有事务，不硬塞成一条通用保存命令。协议Adapter按实际legacy/knownWS2差异选择，未知固件保持只读。

迁移 `WS3UploadFeedback` / `WS3DisplaySettingFeedback` 的拥有者到编辑会话，使子View切换不会丢失本次会话的未确认记录；默认不新增跨App重启恢复或离线自动写入。已确认基线逐字段更新，不能设置整份 `lastSyncedDraft = studioDraft` 来抹掉未提交变更。

现有本地草稿升级不触发设备写入。未知/超长键动作保留原始数据只读；复杂宏按新固件可读回容量计算，不继续误报旧98字节一定可保存。WS3全局亮度与旧版按模式草稿分开；资源ID与四模式画布素材映射明确，缺原始图片字节时不伪造实际预览。

I01先行；I02a/b、I03–I05分批接线；I02c的固件核验提前启动，不能等所有UI完成才核查。I06在各能力迁入后删除对应入口；I07覆盖整个用户路径。每批都应走现有组件入口测试，不能继续以独立设置页通过代替产品流程通过。

本方案不改变F5暂缓、Consumer已验证、原生转写不依赖Runtime的决定，不重复刷写。固件owner释放与CP3仍按已有风险清单跟踪。

## 已确认产品决定（2026-10-22）

以下决定均由用户明确确认，已经整合到上文布局与WBS；本轮不实施客户端或固件修改。

1. 保存仅作用于当前组件，其他模式/组件草稿保留。全局设置影响范围必须另行标明。
2. 编辑草稿时保持Agent连接；仅实际读取、保存、明确预览期间临时让App接管，结束即交还。保存前仍重读并核对，不能以旧快照直接写入。
3. 保存前读值与初始基线不一致：停止本次写入，显示最新键盘值与待修改值，保留草稿；用户明确确认修改或采用设备值。普通保存不新增确认；写后读回不一致是保存未确认，不伪装成普通冲突或成功。
4. 素材上传期间固定组件和模式，直到完成或明确取消再离开。取消可能已覆盖部分素材，不能声称撤销；当前固件可能需正常重启释放上传事务。
5. Voice按模式独立，可设为Consumer系统听写、App原生转写、AhaType，或普通自定义快捷键触发第三方软件；必须支持四模式混用。自定义直发不应被App语音路由额外截获。

6. 拨杆仅展示实体档位/审批状态，不提供软件切档；保留默认收起的高级两档绑定编辑区。

### Voice新增范围与依据

接受固件源70ca334的main.c中`voice_onboarding_mac_consumer_voice_active`检查全局onboardingState；command_solve.c的0x96写接口仅接受全局SUPPRESSED_BY_DESKTOP。尚需核对按键分发分支，不能只根据全局标志断言完整可行或仅改单项绑定即可实现Consumer混用。

客户端ConfirmedVoiceHandoff/VoiceHandoffHost当前统一准备四模式F18；ConfirmedOrdinaryKeySetting在固件语音预设接管时禁止改Key1动作。VoiceRelayService已有按模式路由，但自定义F19有Fn中转特例，不能把所有自定义路径概括为直接发送。NativeSpeechTranscriptionService的AhaType短/长按开关当前为全局。

因此需新增：逐模式语音策略和已确认事实、直发与App接管明确分离、原生/AhaType逐模式生效、录音开始后锁定本次方案，以及Consumer混用的固件分发/持久化/读回合同核验与必要改造。Fn/Globe不能未经验证承诺和普通Command/Option组合键具有相同直发能力。

现有键盘仍保持已验证配置；不自动关闭Consumer、不重写四模式绑定、不因编辑草稿更新实际语音接管。可以分批开发，但最终完整目标不得以隐藏Consumer混用入口冒充完成。

### 本轮风险收口

- 产品已确认：当前组件保存、按操作临时交接、保存前冲突明确选择、上传固定目标、四模式语音独立混用、拨杆高级绑定保留。
- 工程必须保证：读写目标固定、逐项结果与部分成功区分、取消/换代/迟到完成撤销、编辑路由不提前生效、普通自定义快捷键不额外转写、按键按下/释放配对、录音期间不随实体模式改变本次处理方案。
- 固件依赖：Consumer逐模式分发及其可逆配置/读回合同仍待核验，不能仅删全局保护后开放写入。独立Fn/Globe直发也不能当作普通Command组合键能力直接承诺。
- 已知限制：上传取消后固件owner释放可能需正常重启（Issue7）；无原素材字节备份，不承诺撤销覆盖；旧固件容量/帧率与新固件分别展示。
- 验收：先自动回归票据/冲突/部分成功，再从虚拟键盘入口逐组件真机；语音需四模式混用、App退出时自定义直发、无重复触发/修饰键滞留及重启保持；不能继续用独立面板HIL替代产品入口验收。

用户已确认以上为终版方案。后续开发以本文件为依据，分批实现/审查/真机验收，PR目标connect&talk；不将本文件定稿等同于代码实现或固件能力已完成。
