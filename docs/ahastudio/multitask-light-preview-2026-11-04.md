# 多任务灯效联动与预览

本次补齐既有灯条侧栏的多任务页，不新增设置入口。原实现只有四段静态说明，虚拟键盘仍使用单任务灯效，也没有向键盘播放多任务示例的入口。

## 客户端行为

- 选择“多任务灯效”，虚拟灯条与右侧示意共用同一时钟：默认三个模拟会话，依次为进行中（绿）、等待处理（黄）、已完成（红），第四段为空。每三秒切换部分会话状态。
- 新会话出现或状态变化时，仅对应分段以约0.6秒周期闪烁三次，随后稳定；未改变的分段不闪，重复轮询不会重新触发。减少动态效果开启时仅显示颜色。
- 白色播放图标位于示意区右下方，hover“预览到键盘”。播放前确认当前设备及已验证的显示能力，再临时接管连接约10秒。期间OLED也会展示模拟任务，说明在播放按钮旁明确提示。
- 不添加真实任务、不发送模型请求、不写Flash、不保存灯效或亮度。播放结束/取消时先清空四槽，再回单任务模式，最后交还Agent；恢复日常后台时遵循现有连接交接规则，不承诺重放旧连接的多任务方式。
- 激活可能已生效但ACK丢失时仍尝试清理；未通过能力验证、未开始切模式时绝不发送清理写入。断连/设备变化会停止发送，清理失败使当前响应通道失效并显示错误。
- 真实多任务由只读任务概览映射槽位。窗口前台时最多每秒读取一次，不写键盘；离开前台或视图销毁取消轮询。图层时钟负责动画，不以高频SwiftUI布局实现闪烁。断连/回单任务立即移除旧分段。

## 固件配合：实体灯珠状态变化闪烁（新增体验需求，尚未完成）

精确核对Fireware-harness@72346b001710d573980a7d398b9e0dced8ff627c，`APP/sub_main/main.c`的`task_render_multi_leds()`按快照直接为每槽两个灯珠写固定绿色/黄色/红色；没有闪烁计时。`display_presentation_apply_multi_snapshot()`保存valid/state/foreground，0x99合同也没有灯效播放参数。因此当前F99D在新客户端播放三会话预览时仍是实体常亮，不可将虚拟闪烁当作实体已通过。

建议固件在现有快照应用/渲染处增加本地临时状态，无需改变0x99协议：

1. 比较每槽旧valid/state与新valid/state；空→有效或状态变化时启动该槽1.8秒闪烁，约0.6秒周期、三次亮暗，结束回稳定颜色。
2. 同值重复快照和心跳不重启闪烁；其他槽不受影响。foreground变化也不重启状态闪烁。
3. 颜色与槽位不变，空槽立刻熄灭；总亮度仍服从全局亮度。使用系统tick，渲染不得阻塞或写Flash。
4. 模式切换、快照清空、断连、过期、休眠清理计时，禁止下一连接继承旧闪烁。
5. 验证三槽同时变更、单槽变更、重复报文、过期/睡眠、OLED不受影响，检查刷新频率与功耗。固件测试通过后提供精确源码与HEX摘要，再进行真实刷写验收。

不通过交替发送“空快照/有效快照”模拟实体闪烁：那会反复改变任务存在性与OLED选择，并增加BLE命令负担。
