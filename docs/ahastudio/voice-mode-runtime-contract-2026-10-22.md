# I02b-1：按模式语音路由与按键生命周期

基线：connect&talk ca7981f（PR153）。本批是I02b运行时第一部分，不宣称完整Key1原位配置、原生/AhaType逐模式设置或Consumer混用已完成。

## 本批行为

- 使用最后上报的键盘工作模式匹配当前按键/修饰键；当前模式没有路由时不借用其他模式的候选。启动前仍保留旧版mode0初值，完整已确认模式新鲜度与设备身份门控随后续配置会话实现，不在本批假称已完成。
- 按下时选择并保存VoiceRoute；松开只按该次按下的路由释放，忽略松开时的模式/修饰键/新配置。松开消费仅一次，孤立松开不开始语音。
- 未接管的按下保持直发，期间新增路由不能抢走其重复/松开；自动重复和重复down不重复开始录音或Fn按住。
- 自定义快捷键全部直发，包括F18/F19；旧“custom F19自动转Fn”的隐含行为停止。需要Fn转发的用户使用显式Fn/Globe预设，已有Typeless/微信/豆包预设与mode0出厂F18兼容别名保留，但别名不跨模式。
- 监听停止或tap被系统禁用时清按下状态、释放已合成Fn，并取消待定原生按键计时；取消不能被当作短按开启录音，长按录音按既有结束流程处理。物理事件到NativeSpeech的down/up/cancel通过主队列FIFO投递。
- 路由配置改变可以按既有规则提前释放Fn，但后续原始keyup仍按旧press消费，不泄漏该次已接管释放。

## 实现与验收

VoicePressRouter由VoiceRelayService真实CGEventTap调用，类型使用实际VoiceRoute/VoiceTriggerBinding/VoiceRouteAction，不另造测试匹配器。共享buildRoutes供回归使用，保持属性不可变。

测试覆盖模式不回退、共用触发键按模式选择、改模式/修饰键/配置后原路由释放、未接管press不被新配置抢走、孤立up/重复不启动、reset后新press、多个key独立释放、直发route重复、custom F18/F19无App路由、mode0 Fn别名不截获其他模式custom。

本批不写键盘、不关闭Consumer、不重绑四个Voice，也不新增Runtime依赖。保持本机当前已验证App方案。真实语音识别/回填、模式混用设备配置、录音处理策略锁定和完整失败矩阵仍待联合验收；不能以纯路由测试声称麦克风/云端/实体按键全通过。
