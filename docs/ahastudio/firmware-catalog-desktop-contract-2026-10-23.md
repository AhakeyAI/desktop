# Desktop 固件目录与升级核验合同（实现中）

## 范围与真实依据

对应总WBS G50/G51/G52/G53。当前固件 Harness 头076382b的WS4/5 PRD要求Desktop维护目录；Stage B架构仍未验收，本文定义的是客户端实现的版本1候选格式，不声称已成为固件发布方确认的官方合同。不会新增固件命令。0x9F仍返回catalog key，0x00仍提供独立设备状态。

## 目录信任

`FirmwareReleaseCatalog`版本1记录revision、每key唯一的硬件/协议profile、能力集合、最低客户端版本、客户端variant、可见性、渠道、发布顺序、推荐/恢复标记、限制及HEX来源。目录最多1MiB、1024条，HEX最多16MiB。URL仅允许无凭据HTTPS；包内路径不得越界。

`FirmwareCatalogEnvelope`保存keyID、精确原始payload的base64、payload SHA-256和Ed25519签名。验签使用客户端固定公钥，既不信任下载所附公钥，也不允许从任意解码JSON创建可信目录。签名只证明发布来源，不能代替实际设备身份、协议实现及逐设置读回。

`FirmwareCatalogStore`按内置工程profile→有效签名随包目录→有效签名缓存选择。坏缓存回退；主动刷新验签/格式/兼容数据不合法、revision倒退或相同revision改内容时，保留当前目录和旧缓存。接受更新先原子持久化再替换内存。刷新只由明确操作调用，不设置轮询，也不因未知key自动访问网络。

现有内置工程profile只保留已经确认的WS2协议识别；无公开HEX、无推荐或恢复安全标记。正式公钥、目录签名流程、公开发布数据和recovery-safe镜像尚需发布方提供，不将测试密钥或工程镜像塞入生产信任列表。

## 候选和兼容

分别表达读key失败、旧协议、未知key、目录不可用、客户端太旧、错误硬件/variant/未实现协议。非ready状态不提供高级能力。候选只来自可信目录中的用户可见渠道，按key去重，同一行可有推荐/最新/稳定恢复/当前标签。客户端过旧的最新版可展示但不可安装；推荐从兼容稳定版选择。读key失败不允许普通目录升级，手工救援另行明确确认。

本地HEX只有与唯一兼容可信稳定条目的SHA完全匹配时才可关联已知发布身份。相同SHA映射多个key属于不确定，不能取第一条。未知HEX可作为明确确认的高级本地文件，不获得推荐/恢复安全标签。

## 下载与刷后结果

目录候选必须核对精确文件字节数和SHA，此外仍需Intel HEX结构/记录校验和/CH582地址范围、ISP实际芯片核验及已校验临时副本。实现这些校验不能被标为真实刷写通过。

WCH写入/代码校验只完成第一阶段。最终验证需要用户移除BOOT短接并正常启动，客户端在同一次新连接上读取有效状态和catalog key，与预期key（包含硬件/profile）一致。缺少预期身份、读状态失败、连接代次改变、key缺失或不一致均不报最终成功。读回key不证明HEX字节版本，只证明目录所约定协议身份。

## 开发与验收顺序

遵循用户最新要求：先补开发和必要的局部自动检查，再整批跑自动/非实体验收；所有按键、拨杆、观察屏幕和断电操作留到最终一次集中配合。Consumer逐模式、CP3、独立长按、整机恢复合同尚未提供的部分继续保留完整要求；缺协议不能记作完成。固件目录/升级模型完成也不等于候选界面、下载、刷后连接适配和正式发布组合全部完成。

## 本轮实现证据

9项目录/签名/缓存/候选/精确文件/刷后模型测试通过；连同既有HEX和能力识别共25项相关测试通过。App与Agent编译通过。两轴审查发现并已关闭：刷新目录后旧候选文件仍可开刷、本地HEX唯一可信匹配未接线、新动态状态缺少英文译文。已用完整候选票据同时约束开始按钮与最终确认；本地文件匹配SHA和大小；新增状态及徽章补齐中英文本地化。审查复核通过。
