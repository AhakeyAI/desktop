## 持久化及失败语义

- 普通键由73改变工作配置，再04调用`save_key_bound_data()`。该保存函数没有向调用方提供统一可验证的事务成功结果；RAM读回一致不等于断电持久化已证明。客户端已有未确认标记、同值重试保护与“断电保持尚未验证”提示，不能新加假回滚。
- 待机95先修改RAM/生命周期阈值，再保存并EEPROM读取该字段核对；保存失败时运行值可能已经变化，必须保留未确认状态，不自动用旧值覆盖。
- Voice96调用专用magic/state持久化并校验，只接受suppress3；状态与普通按键独立。分模式Consumer仍是固件Issue8的增量合同，不因目录支持而可用。
- 拨杆97保存两位置绑定后ACK；无整段持久化比较结果。客户端确认实际绑定仍不能替代断电验收；物理位置与审批策略仍以实时实体值为准。
- 亮度/灯效8E由display_config_store返回存储结果；客户端还核对所选设置和其他位置范围，不能把36项批次部分成功称为全成功。
- 素材由资源元数据和CRC/事务状态确认，帧槽28672字节、编码25600字节、各位置容量继续使用WS3既有合同。有效metadata/CRC不等于完整视觉验收；一次上传中断不能保证恢复以前的图。

客户端不编码固件key_bund内存布局，不读取/写入EEPROM裸地址，不把资源元数据版本、catalog key、目录schema1或App草稿schema当成同一种版本。目录签名只授予已实现且兼容的协议识别，不替代连接内能力证明。正式新key能力治理在App/Agent统一接入前，不对未知key解锁已有写路径。

## 连接与证据边界

每个操作持有短租约、设备ID和连接代次；读取后、下一条写入前及完成后复核。断连/错误刷新清除事实；迟到旧操作不能释放新租约。固件也用transport/generation/handle标识资源事务owner；客户端配置连接关闭不保证系统HID物理链路丢失，继续保留Issue7的固件优化要求。

自动样例覆盖目录/普通键/待机/Voice/拨杆/显示/资源/取消/连接代次的各自测试文件。新增命名空间测试不能替代全部旧固件或SDK真机兼容；统一留至后续自动矩阵及最终实体集中验收。

## App / Agent 统一运行时能力治理

已接入 FirmwareRuntimeCatalog：App 及嵌入 Agent 从同一签名 App 的 FirmwareFlasher 资源加载公钥/内置目录，从外层 App 读取数字版本，使用同一最后有效缓存路径。无网络、无轮询、无从下载内容读取公钥。只有操作开始时检查 inode/mtime/大小变化，变化才重新验签；倒退、同 revision 不同 payload、坏签名均保留最后有效目录。

缓存读取的 stamp 必须对应读前状态。初始化和本地写后不采样事后 stamp，而保留待重读状态，避免另一进程原子替换期间产生“旧目录＋新文件 stamp”并长期漏掉收权。

0x9F 仍报告原始 key。已签名且硬件/variant/最低版本/p1 合同兼容的记录产生带真实 key 和能力集合的 profile；未知、不兼容、factory key 不开放高级操作。当前内置工程 key 保持既有兼容，但正式签名目录若限制同 key 的能力或移除 key，不继续套用内置全能力。普通键/语音 onboarding/实体拨杆/待机/显示/素材/多任务分别受各自能力约束；语音接管还需普通键能力，素材/呈现还需显示能力。没有扩展固件 opcode 或存储 schema。

目录能力只允许对应只读探测及进入既有确认事务；写入仍需当前连接读回、窄授权和实际 ACK/核对。canWriteWithoutReadback、无条件 WS3 写标志继续为 false。Agent 每次审批先取当前目录快照，再读取实际状态/key/绑定并复查连接；实体自动档、出厂自动绑定和新鲜状态缺一均不自动放行。

App/Agent 共用 WS3PresentationSession。激活通过实际 key/显示读回获得绑定后，后续每条 0x98/99 写前重新检查当前目录权限。有效目录收回呈现能力或 key 后，停止发送并清运行时/故障断连，不继续使用激活时的旧授权；同模式重复选择也复核。所有异步授权与失败清理均绑定连接及呈现代次，旧等待返回不能清除新连接。尚未将此局部代码证据当成真实双 owner/OLED/断连验收。
