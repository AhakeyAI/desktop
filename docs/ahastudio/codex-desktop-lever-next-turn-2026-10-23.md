# Codex 实体拨杆控制原会话权限：下一轮生效

2026-10-23，用户已确认：由实体拨杆直接切换 Codex 会话的完全访问／请求批准，胶囊只取得明确授权；接受同一会话下一轮生效，不要求先手动设置请求批准。

## 与已安装版本的区别

build371 的胶囊仅修改默认配置，不改变已有会话。这是旧实现，不是本方案完成证据。无自动授权时 Hook 仍须不返回决定，继续原生审批或完全访问链路；此规则保留。

新方案须同时改变权限范围与审批策略。自动为完全访问及 never；手动为已确认的受限权限 profile 及 on-request。只写 never 不能等同完全访问，只写 on-request 但保留无限权限也不能等同普通请求批准模式。

首次确认须说明 Studio 将随实体拨杆管理识别到的本地 Codex 会话及下一轮生效范围。旧 codexApprovalSetupChoice=requestedApproval 只授权修改默认值，不能自动升级为授予完全访问的授权。拒绝后零权限写入，保留原生行为；不得用 deny 替代未接管。

## 已查明的真实接口

官方 [App Server 文档](https://learn.chatgpt.com/docs/app-server) 说明初始化与 Unix/WebSocket 传输。以下实验性设置字段依据本机实际 CLI 生成的 schema，不冒充官方文档已作稳定承诺。

- 桌面内置 CLI 为 0.163.0-alpha.11；共享 daemon 为 0.164.0。两者不是同一进程或会话所有者。
- 两版的实验性 thread/settings/update 支持 subsequent turns 的 approvalPolicy、permissions 或 sandboxPolicy；permissions 与 sandboxPolicy 不能组合。
- 当前运行轮次的 turn/settings/update 不接受 approvalPolicy／sandboxPolicy。隔离进程实际拒绝未知字段，不尝试修改当前轮。
- 在临时内存会话上，0.164.0 已实际返回 on-request+workspaceWrite、never+dangerFullAccess 的设置通知；无 turn/start、无供应商请求、未修改生产会话。
- 共享 daemon 能读到本会话历史，但报告 notLoaded。不能通过 resume 在该服务加载第二份会话来冒充控制桌面原会话。
- 桌面另有同用户 IPC 路由：thread-owner-discovery v1 能定位真实持有者；thread-follower-update-thread-settings v2 定向原持有者，省略 activeTurnId 走下一轮设置路径。内置客户端会同步其会话状态，避免仅改旁路服务。
- Python 探测与新增 Swift 生产传输均已在真实桌面完成只读持有者发现。客户端自报 ahakey-studio，不冒充桌面，不读取令牌或认证文件；没有写生产权限或发起模型请求。

## 本批代码范围与证据

新增 CodexDesktopSessionBridge：私有目录和 socket 权限／同用户 peer 检查，4字节小端 JSON 帧、有限帧长与总截止时间；初始化、原持有者发现、写前重新定位、定向提交及 applied=true 确认。失联或持有者变化直接报告未同步，不 resume／start，不改默认 config，不把失败回成原生 Hook 拒绝。

15项局部回归覆盖原持有者、下一轮参数、两项权限一起设置、手动 profile、持有者变化、错误确认、无效目标、拒绝不安全 endpoint，以及真实本地 socket 的初始化和分片帧。新增最小权限基线，完整保留自定义受限目录与网络设置，拒绝混入模型等无关字段；新授权和写前日志独立存储、原始基线不被跨档覆盖、迟到确认不能清除新操作、损坏记录不能重置为成功。生产 Swift 传输在真实桌面只读发现和权限读回均通过。机器可读收据见 [native-session-bridge-2026-10-23.json](../validation/connect-talk-hil-2026-10-22/native-session-bridge-2026-10-23.json)。

桌面当前没有轻量权限读取方法。一次性状态订阅会在内存接收包含已加载历史的完整快照，本会话约29 MB；仅提取权限字段，随即取消订阅并丢弃其余内容，不保存快照，不请求额外历史。代码设置64 MiB和6秒上限，不允许用此路径轮询；未来协调器须合并快速切档并限制读回次数，性能仍须验收。

这是桥接与恢复日志基础，**尚未接入发布路径**。不把原持有者发现、隔离 native 设置成功或夹具 applied 确认，描述为真实生产会话已经随拨杆切换。

## 接续开发和验收门槛

1. 明确授权／写前恢复日志存储已有实现，尚需接入新的胶囊与Agent；不迁移旧默认配置授权，不再要求手动初始化 Codex 权限。
2. 从真实 Hook 获取会话身份，限定本机原持有者；独立维护会话目标，不使用任务概览的哈希或文件名猜测目标。
3. 采用 Agent 的实时有效自动证明和出厂绑定核验，不能仅凭 GPIO=0；自定义拨杆绑定、暂停、断连和退出须进入明确的接管收尾状态。
4. 同一会话串行处理快速跨档，撤销旧请求发布权并补做必要的权限恢复；处理请求已发送但确认丢失、原持有者重启、Agent 重启与退出、撤销授权和不再拥有的用户设置。不能留下无人管理的完全访问租约。
5. 使用原持有者实际支持的 profile，保留／明确处理自定义受限范围；拒绝与不支持都显示未同步，不以修改全局配置兜底。
6. 完成原桌面的实际接受和读回／界面一致性验证，再验证下一轮；不能把当前轮仍沿用旧权限当成失败或假称即时改变。不得启动额外收费模型请求补验已用完的 Cursor 授权。
7. UI 清楚区分启用管理、等待会话、同步中、下一轮已接受、未同步；补齐自动→手动、暂停、断连、退出及重启矩阵。原版 CLI 无桌面持有者时继续原有 Hook 路径，不伪装受控。

接口属于桌面内部实验性协作入口，需要版本回归和能力失败降级；不能承诺第三方桌面版本永久兼容。用户目标仍保留，当前不标开发完成。
