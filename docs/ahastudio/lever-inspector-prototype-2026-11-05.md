# 拨杆侧栏改版 — 交互原型

状态：用户已选择A并继续细化为两档始终展开的表单；生产SwiftUI已按该方向实现，最终1051项回归通过，候选打包和原生界面验收进行中，尚未替换已安装客户端。

## 已确定的产品要求

- 当前实体档位仅在查看态展示，编辑态聚焦设置。
- 两档拨动动作是整把键盘的全局设置，保持原虚拟拨杆→修改→侧栏链路。
- 键盘Mode是不同的自定义键位配置，不限定IDE；所有Mode下都能查看Claude、Cursor、Codex、Kimi审批策略，IDE筛选独立于键盘Mode。
- 硬件动作统一由底部一个“写入键盘”提交；会话授权另行确认，不能悄悄混入键盘写入。
- 不提供软件切换实体档位；查看态不放会话管理按钮。

## 可交互方案

| 方案 | 结构 | 取舍 |
|---|---|---|
| A（推荐） | 上方两档动作卡，一次展开一档；下方独立IDE Tab和审批卡 | 动作和审批关系直观，少一级模块切换；长宏仍需滚动 |
| B | “拨动动作／Agent审批”双标签；动作摘要表＋编辑面板，审批四卡平铺 | 操作区更聚焦；查看另一类内容需切一次标签 |
| C | 左侧位置1／位置2／审批导航，右侧对应详情 | 单次信息最少；窄侧栏详情宽度受限 |

动作入口直接平铺为出厂自动、出厂手动、快捷键、宏、不执行，去掉“自定义→动作类型”的重复层级。原型支持快捷键修饰键、宏步骤增删、配对提示、草稿点、写入成功后的继续编辑／完成编辑，以及返回查看态。位置1离开出厂自动绑定时，给出写入后自动批准暂停的上下文提示；不因只修改位置2就泛化提示全部失效。

Agent区以自动档／手动档两列展示策略。Codex说明下一轮生效；Kimi区区分Code Desktop、官方CLI新会话默认和普通Kimi的现有能力，不把未实现接口包装成已支持。

## 运行与检查

原型位于`ahakeyconfig-mac/Prototypes/lever-inspector-prototype.html`：

```sh
python3 -m http.server 18763 --bind 127.0.0.1 --directory ahakeyconfig-mac/Prototypes
```

打开`http://127.0.0.1:18763/lever-inspector-prototype.html?variant=A`；底部箭头切换A/B/C，URL可直接指定方案。按已有用户要求继续使用connect&talk，不新增原型分支。它不进入App打包资源，全部数据仅在内存中，写入/授权均是演示，没有连接设备、账号或后台IPC。

已在窄侧栏和桌面上下文检查A/B/C，修正图标默认尺寸造成的留白；实际点击检查Mode和IDE独立切换、快捷键草稿保留、查看态才出现当前档位。完成截图后恢复了浏览器默认尺寸。本轮没有新增单元测试，也不以原型证明生产事务通过。
