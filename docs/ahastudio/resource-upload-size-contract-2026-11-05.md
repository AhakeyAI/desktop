# 素材快速写入：50KB 目标与现有协议边界

已按Owner要求在固件仓库单独提交并读回确认：[Issue #18：支持低分辨率与压缩素材上传，实际载荷目标≤50KB](https://github.com/AhakeyAI/AhaKey-X1-hardware-source/issues/18)。该项为协议扩展，不与取消恢复Issue #10混为一项。

Owner要求自动降低尺寸及抽帧，使实际传输量不超过50KB，并尽量在几十秒内完成。不能以JPEG/GIF源文件大小作为达标依据。

当前客户端与F99D采用固定帧格式：160×80×2＝25,600字节可见RGB565数据，每帧补齐至28,672字节。两帧为57,344字节，超过50KB及50KiB。降低源图分辨率后仍编码成固定屏幕帧，故不会减少该协议的传输量；较短载荷不满足现有合同。该限制属于当前格式，而不是屏幕硬件必然要求图片都为28KiB。

静态图单帧已小于50KB。现有GIF不能同时满足“保留动画”和“总量小于50KB”；不能擅自将动画改成静图并标记为压缩成功。Owner尚未选择该取舍，现有上传行为保持不变。

若保留动画，需协同固件引入可协商的压缩/低分辨率传输格式，由固件解码或缩放到屏幕布局；须明确尺寸、帧数、编码、校验、容量及旧固件回退。跳过补齐或修改客户端CHUNK上限不能替代固件支持。

旧组合的一帧实传观测约558字节/秒：单帧约51秒，50KB约90秒，均未计全部交接开销。因此体积限制本身不是固定时延承诺；快速传输还需独立验收吞吐量、失败重试及完整性。
