版本：2026-10-19 v1。状态：产品决策已逐项确认，用户要求发布本文及固件清单，交接对应同学做实现落地。协议细节、技术方案和验收证据仍须补齐；本文所述整合目标尚未实施。源码复核基线见下表，固件增量范围见配套清单。

本文汇总当前有效的用户决定，发布于 Desktop 仓库 runtime 分支，供对应同学进行技术设计、WBS 与实现落地。若此前历史方案与本文不同，以本文为准。固件交接需求见 [固件改动清单](firmware-integration-change-list.md)。

## 1. 范围与基线

- 当前重点为 macOS。允许分批开发和内部验收，正式发布前须迁齐当前 Mac 客户端已提供、且目标固件实际支持的功能：配置、OLED、拨杆与 Hook、既有语音预设、后台运行和相应系统集成。实施前从最新 Desktop main 列出具名功能对照表，不以本文列举代替源代码盘点。
- 本轮额外承诺：可逆 Consumer Voice / AhaType 切换、后台云端音频转写、完整设备配置读回、保留配置的 Studio 内固件升级。
- Windows 可独立发布；保留现行 Ctrl+Win 默认，本轮不继续设计 Windows 语音。F5 机制取消。
- 固件 WS3/WS4/WS5 中尚未完成的新产品能力不自动加入本轮；但为满足上述已承诺行为所需的协议和固件改动仍是依赖。

**2026-10-19 最新代码复核后的 OLED 决策：**优先采用新固件的资源模型和真实能力；客户端按固件版本/能力 profile 展示相应限制与说明，不再要求所有新固件保持旧版 70 帧及 1–30 FPS。以已核对 CP2 源码为例，默认资源最多 8 帧、状态资源最多 12 帧、资源播放间隔固定 100ms；这些是该 profile 的能力，不是其他版本的通用值。旧 profile 经核实后展示其原有限制。由于当前新旧 catalog 相同，profile 选择须依赖可验证的构建/协议能力，不能只看界面版本号或通用 ACK。此决定不授权静默裁剪、改速或丢弃旧资源。用户已确认：仅在用户主动执行固件更新流程时，且擦除/刷写之前，检查旧资源兼容性；不兼容时展示转换预览，可靠备份原资源，经用户确认后转换。无法可靠备份或用户不接受转换，则暂停升级。日常连接和读取配置不自动转换资源。

## 2. 唯一设备 owner 与进程生命周期

正式版由 Rust Runtime 唯一持有设备连接。Studio 提供界面，通过 Runtime 查询、提交和订阅状态；Swift Agent 的设备和后台职责逐项迁移，最终退出设备控制链。沿用现有共享设备锁的兼容约束，避免新旧后台同时占有设备。

| 事件 | 预期行为 |
| --- | --- |
| 打开 Studio，Runtime 已运行 | 连接已有 Runtime，不重复启动 |
| 打开 Studio，Runtime 未运行 | 自动启动，再建立客户端连接 |
| 完全退出 Studio | Runtime 及已就绪的 AhaType 后台链路继续运行 |
| Studio 内主动关闭 Runtime | 保持关闭，直到下一次打开 Studio；不被崩溃恢复机制立即拉起 |
| Runtime 意外崩溃 | 后台管理程序自动尝试重启；恢复期间 Voice 走 Consumer，语音链路就绪后按用户选择恢复 |
| 电脑重启但未打开 Studio | 不主动启动 Runtime；Voice 默认走 Consumer |

原 Rust 的 `--parent-stdin` 随 App 退出方案不能直接成为上述常驻生命周期。重启退避、失败上限、服务 label、helper 签名和系统授权归属需在技术设计中落实。

## 3. Mac Voice 与 AhaType

### 路由与操作

- 默认保留当前固件 Consumer Voice 行为。Studio 允许随时在“系统 Consumer Voice”和“AhaType”之间切换并切回。
- 选择 AhaType 时，Runtime 的录音、音频转写、麦克风权限、账号鉴权与云服务必须就绪；未就绪时保持 Consumer，并显示原因和设置入口。用户选择与设备实际路由分别表达。
- Runtime 关闭/故障，或按键前已知账号、权限、网络不可用时，回退 Consumer。条件恢复后按用户选择恢复 AhaType；一次按键只能启动一条语音链。
- AhaType 短按一次开始录音，再短按一次结束；长按按住录音、松开结束。短按与长按互斥。Consumer 模式保留系统行为。
- 当前 `0x96 suppress` 不能被假定为可逆路由接口。AhaType 的专用触发形式由固件与 Runtime 技术设计确定；F18 只是可能方案，不能误称当前 Mac 默认触发事件。

### 后台链路与失败

录音、云端音频转写、AhaType 文字整理和输出均由 Runtime 管理，不依赖 Studio 界面进程。平台原生 helper 如有必要，也须由 Runtime 生命周期管理。

首版使用 AhaType 账号与鉴权体系；自定义 API key 留到后续。已有 `/api/v1/typeless/process` 只接收文字整理，不能代替新的音频转写 API。服务端需提供并验证音频转写契约。

| 场景 | 输出与反馈 |
| --- | --- |
| 按键前已知 AhaType 不可用 | 本次走 Consumer，显示原因 |
| 音频转写失败 | 提示重新说一次，不持久保存音频供重试，不事后唤起系统听写 |
| 转写成功，文字整理失败/超时 | 使用原始转写，提示“整理失败，已使用原文” |
| 取消本次语音 | 不输出本次文字；迟到的云端结果不得重新触发输出 |
| 完成时原输入位置仍有焦点 | 自动写入文字 |
| 完成时已切换应用或输入框 | 不自动写入新焦点，提示手动复制 |

Voice 开始时记录目标输入位置。待复制文字只暂存在当前 Runtime 内存；复制、丢弃或 Runtime 退出后清除，不建立长期转写历史。

不抢焦点的小悬浮条展示“录音中 / 转写中 / 整理中”，提供“取消本次”和必要时的“复制文字”。Studio 完全退出后这些反馈和操作仍可用。

既有第三方语音预设按当前 Mac 功能对照表保留；本轮没有授权新增一套第三方工具或重新定义其快捷键。

### 拨杆与审批策略（2026-10-19 确认）

Studio 按拨杆两端的实际绑定展示自动审批、手动审批、禁用或自定义，不将固定物理位置等同于自动审批。Runtime 只有在读到新鲜且验证有效的 Factory Auto 绑定，并确认当前拨杆位于该绑定位置时，才允许自动批准；自定义、禁用或读取失败时保留人工确认。保留现有每次请求核验状态新鲜度的防护。

### 配置期间的调度边界（2026-10-19 确认）

用户明确配置模式下不使用键盘，优先遵循新固件的事务方式。资源上传等配置事务期间允许固件暂不接受语音路由维护、拨杆绑定查询及其他控制命令；此期间不适用日常语音/拨杆 ≤2 秒响应要求。Studio 须明确展示配置/上传中及当前受限状态；Runtime 按固件事务串行调度，不混发被拒绝的命令或无上限重试。此决定不证明普通 HID 输入被固件禁用，也不将仅打开 Studio 自动等同于进入配置事务。日常非配置状态仍适用原响应门槛。用户已确认配置模式自动进入和退出：浏览/编辑草稿不占用配置事务，提交写入后进入，事务结束后退出。写入中的提示弹窗须保留“暂停写入”按钮，供长任务或异常时主动退出配置事务、恢复键盘控制态；不能仅停止客户端发包而让固件停留在活动事务。暂停后保留未完成任务；用户点击“继续写入”时先核对设备当前结果，已成功项目跳过，只处理未完成部分。中断动图若不支持断点续传，仅重新上传该动图，不重写其他已完成项目。已确认成功仍须满足持久保存证据要求；无法核对的部分保留为结果不确定。用户进一步确认：持续没有有效进展或既定重试耗尽时，自动暂停并尝试安全结束配置事务、恢复键盘控制；只有核验恢复后才提示键盘已恢复，无法确认时明确提示异常。任务保留且不自动续写，等待用户主动继续。仍有有效进度的慢上传不因总耗时较长而强制中断；无进展判据及超时参数由协议与实测确定。

## 4. 设备读回与 Studio 展示

1. 连接后优先读取设备配置，覆盖全部设备可编辑项：键位/宏/描述、灯效、亮度、拨杆设置、OLED 当前画面等。OLED 不要求还原原始 GIF 源文件。
2. 底部导航栏显示“读取中”。未全部读到时自动重试最多 3 次；持续失败显示“读取失败”，支持点击手动重试。不得将部分结果标为完整同步。
3. 读取成功后提示“是否将键盘当前设置同步到 Studio 展示”，确认后才刷新界面。先将本地未写入草稿保存为可恢复版本，之后允许比较或恢复；恢复草稿不等于自动写入设备。
4. 未读取项明确显示未知，不能使用本地草稿冒充设备事实。单项写入成功后只更新该项状态，不自动弹整套同步；整套同步留到重连或用户主动读取。

## 5. 逐项写入、重试与并发编辑

- 写入只触碰本次明确修改的项目。其他未修改、未读到的设置保持原样；底层如需重写共享存储块，由固件负责可靠保留其他字段。
- 持续读回失败也允许编辑。写入前提示尚未同步键盘最新设置，将以 Studio 当前值覆盖本次列出的项目；用户确认后才写入，不能扩大成全量覆盖。
- 每次提交冻结字段补丁和草稿修订号；写入期间可继续编辑，新改动保留为“未写入”，不能因旧操作完成而被一并标为同步。
- 写入弹窗提供“暂停写入并恢复键盘”，在可证明安全的边界结束配置事务；显示已生效、未执行和结果不确定的部分，不承诺回滚已生效内容。保留未完成任务供用户主动继续，续写前核对设备结果、跳过已成功项目；不支持断点续传的动图仅重传该动图。

写入超时或断线后自动读回本次项目：已等于目标值则显示成功，不再重写；明确不同时才重试。每次用户提交最多实际写入 3 次（首次 + 2 次重试）。读回也持续失败时，显示“写入结果未确定”和手动重试入口，不盲目重发。

用于重试的读回只属于该操作的核验证据，不自动刷新 Studio 草稿。完整设备同步需等写入终态后重新读取并经用户确认；写入前启动、后来才返回的旧快照不可覆盖新草稿。

“已写入成功”需要证据覆盖本次操作的承诺。如果操作包含持久保存，只读到 RAM 值相同不能单独证明 Flash 保存成功；固件须提供相应保存/版本/校验依据，并做断电保持测试。该证据要求由技术设计闭合，不改变已确定的逐项核对重试体验。

## 6. Studio 内固件升级与旧版迁移

- 用户只在 Studio 点击升级并操作实体键盘。当前硬件关机后长按 Voice 键可进 BOOT，无需拆机；Studio 调用受控工具执行镜像校验、刷写和结果确认，不要求另行操作刷写软件。
- 升级须保留并核验现有键位、宏、灯效、OLED 和语音选择。无法可靠保留或备份时，在刷写前阻止升级并说明。
- 升级中断后只剩 BOOT 时，Studio 仍须识别设备并用已校验镜像引导重刷、核验；只有经真机证明能回滚时才宣称“一键回滚”。
- 旧固件仍可使用实际支持的功能和 Consumer；AhaType 切换入口显示“升级固件后可用”，不锁住整个应用。
- 新 Studio 自动迁移旧 Swift Agent：备份配置与相关 Hook 状态，停旧 Agent，启动 Rust 并验证；接管失败时恢复旧 Agent 和原配置，不要求用户手动卸载后台服务。

## 7. macOS 正式发布门槛

用户已确认以下目标；它们尚不是当前实现已达到的结果。

| 检查 | 门槛 |
| --- | --- |
| 空闲性能 | 真实键盘连接、Release 候选，Studio + Runtime + 所属 helper 合计平均 CPU：前台静态 <2%，后台 <1%；连续采样至少 30 分钟 |
| 测量条件 | 留存机型、macOS、固件、候选身份与原始 CPU/RSS；空闲采样不与录音、转写、上传等活动阶段混算 |
| 稳定性 | 至少 8 小时，包含后台运行、状态变化、断线/重连；无崩溃、持续内存增长、卡键/卡麦克风或配置丢失 |
| 交互响应 | 日常非配置事务期间，实体拨杆及后台状态响应 ≤2 秒；配置事务按新固件互斥规则执行并展示受限状态 |
| 产品验收 | 正式 Release 候选完成现有功能对照、权限/安装、旧版迁移、配置、OLED、Hook、后台语音、固件升级与故障恢复实机验证 |

Runtime 连接空闲 <0.5% 是既有技术规划中的参考预算，可用于定位后台开销；本轮用户确认的发布 CPU 门槛以整套进程合计为准。绝对 RSS 上限待有实际基线后在技术验收方案中设定。

## 8. 下一阶段及尚需技术闭合的依赖

逐项产品讨论已结束，用户已要求将两份文档发布交接给对应同学做实现落地。接手同学据此编制技术方案/WBS，先闭合接口、依赖和现状映射，再分批实施与验收；不得将需求确认当成协议冻结或验收通过。

建议按以下交付边界拆分，具体接口与依赖在 WBS 中固定：

1. **双仓基线和兼容契约。** 复核最新 Desktop main / Rust dev / 固件差异，准备独立客户端 checkout；建立单一 schema 来源和同步验证，盘点具名功能、权限和后台模块。
2. **Runtime owner 与 Studio 接入。** 完成发现、认证、订阅、能力展示、服务生命周期、唯一连接锁及旧 Agent 可恢复迁移。
3. **配置和 OLED 闭环。** 依赖固件完整/逐项读回与提交结果证据，落地草稿、用户确认同步、逐项写入、超时核对、取消和旧快照隔离。
4. **后台语音闭环。** 联合固件可逆路由/host 有效性及 AhaType 音频转写 API，迁入录音、云端、整理、输出和后台浮条。
5. **升级和发布。** 资格验证后的刷写工具、镜像及资源保留/BOOT 恢复，与完整功能、性能和稳定性验收收口。

技术阻塞不能伪装成产品已经完成：完整读回/导出及保存证据、可逆语音协议、音频转写 API、可保留配置的刷写工具链均需拿到可运行实现和验证。旧 Studio smoke 不能代替新 Desktop 的集成测试。远端变化也不自动授权重写固件其他工作流或开放尚未接受的 WS3/WS4/WS5 功能。
